# v0.3.0 Release Notes — Draft

> **Unreleased draft.** Version `0.3.0` is the repository version, but it has not been published to npm. No release date or GitHub Release exists yet.

For upgrade steps from v0.2.1, see the [v0.3 migration guide](../migration/v0.3.md).

## Highlights

- Reactive standard collections by default inside `deepSignal`.
- Explicit JSX form bindings and a new opt-in Lite runtime for Signal children.
- A narrower Managed Transform capture contract with diagnostics and multiple bundler integrations.

## Added / Expanded

- Writable `computed({ get, set })` and `useComputed({ get, set })` values, with writable capability represented in TypeScript.
- Explicit `bindValue` / `bindChecked` form bindings, including text, number and range inputs, textarea, select, radio and checkbox groups, native event ordering, reset, SSR/hydration, and IME handling.
- An opt-in `react-fine-grained-signals/lite` JSX runtime, added alongside the existing Full runtime, for ordinary JSX and Signal children without Full's direct-binding implementation.
- Reactive `Map`, `Set`, `WeakMap`, and `WeakSet` behavior by default for supported same-realm collections inside `deepSignal`.
- `Match` value comparisons with `equals` and `useDeepSignalValue` selectors with optional dependencies; existing `For` / `Index` utilities remain unchanged. `Match equals` lets `Switch` subscribe to the condition without making the parent subscribe.
- Managed Transform diagnostics `RFGS001`–`RFGS009` and opt-in `diagnostics.errorOn` build errors.

## Changed / Breaking Changes

- Same-realm standard collections inside `deepSignal` are reactive by default; v0.2.1 read-only collection views and the old collection opt-in are removed. Values accessed through the proxy have reactive proxy identity, and mutations through raw references or `.peek()` do not notify.
- Signal-valued `value` / `checked` are no longer implicit JSX direct bindings. Use React controlled props with `.value` and `onChange`, or the explicit writable `bindValue` / `bindChecked` props under Full JSX.
- Managed Transform replaces v0.2.1's whole-function ambient collection with a top-level capture Hook and statically proven synchronous per-read capture. Review helper, alias, callback, and asynchronous read boundaries in the migration guide.
- `useComputed` now validates dependency mode, length, and readonly/writable capability changes. These invalid Hook contract changes fail clearly instead of keeping stale memoized closures; `useSignalEffect` rejects dependency length changes.

## Fixed / Hardened

- Fixed the confirmed Managed Transform control-flow diagnostic false positive, unsafe tracked-parameter relocation, missing Update/Delete capture, JSX binding-ref churn, classic Fragment Signal-child handling, and unsupported Signal-valued host prop leakage. Bounded pruning reclaims stale Deep Signal key metadata after dependency switches and later activity, and final-unsubscribe notification schedules cleanup. See the [Opus review resolution record](../../development/v0.3.0/m19-opus-findings-final-closure.ja.md).

- A Signal written while a concurrent (transition) render yields no longer commits a mixed snapshot. Before the fix, a `useSignalTracking()` component or `useDeepSignalValue` mounted in that render could commit the old value next to siblings showing the new one until a follow-up commit; this already happened in v0.2.1. Both now take part in React's render-end `useSyncExternalStore` consistency check, including reads through computeds, so React redoes the render once, synchronously, before committing. The same change stops `useDeepSignalValue` from committing a stale selection when an `Activity` boundary is revealed. See the [M19.4 record](../../development/v0.3.0/m19.4-r1-concurrent-commit-consistency.ja.md).

## Existing in v0.2.1 (not new in v0.3.0)

- React 19 or newer, Node.js 22 or newer for the runtime package, and the ESM-only package format.
- The opt-in Full JSX runtime, including Signal children and its documented native-host attribute/style binding surface.
- `For` and `Index` control-flow components.

The transform package's Node.js `^22.18.0 || >=24.11.0` requirement applies to the current Babel 8-based plugin.

## Performance / Bundle

- In the M18.22 Node v24.21.0 Windows x64 measurement, eliminating the temporary node `fields` object reduced GC-retained heap by about 8 bytes per object when 50,000 Signal, readonly computed, or writable computed objects were retained. CPU time did not show a reliable improvement. This is a workload-specific memory measurement, not a per-application performance guarantee.
- The same exact bundle check measured `index-full` gzip at 24,672 bytes after the change, versus 24,697 bytes at its M18.21 baseline; all existing budgets remained unchanged. Bundle output depends on the consumer and toolchain.
- Lite reduced gzip size by 6,029 bytes versus Full in the M18.17 small production Consumer fixture. Importing Full and Lite together can erase or reverse that saving; this is not a fixed package-size guarantee. See the [JSX guide](../guides/jsx-bindings.md#setup).

## Known Limitations

- Managed capture is limited to statically analyzable synchronous reads. `mode: "auto"` does not select a caller solely because an imported helper reads a Signal; `transform: "inject"` and hand-written `useSignalTracking()` provide best-effort ambient tracking. Use an explicit `useManagedSignals()` lexical boundary when required.
- Managed Transform can follow supported same-module synchronous helper calls and tracked local aliases, including hoisted function declarations and nested helper calls. It does not infer Deep Signal proxy provenance across props, custom Hook returns, or `useMemo`, and does not generally infer Signal reads from arbitrary property getters or callbacks whose synchronous invocation cannot be established. Some same-module synchronous helper calls from getters are recognized, but getter bodies are not generally analyzed. When such a read must be tracked, expose a managed-recognized synchronous read or use a first-statement `useSignalTracking()` / `transform: "inject"` ambient boundary (best-effort). With `mode: "auto"`, the function still needs a recognized read or explicit opt-in to be selected; `transform: "inject"` alone does not select it.
- Full JSX direct binding is deliberately limited to documented native host elements and props. Lite supports Signal children only. Neither runtime unwraps Signals passed as React component props.
- JSX direct binding owns the bound DOM props. `cloneElement`, Slot, and `asChild` wrappers that inject competing values such as `value`, `checked`, or another bound attribute can override or conflict with that owner; attach the binding to the final host element and avoid competing injected values.
- `deepSignal` supports same-realm standard collections. Raw references and `.peek()` bypass reactive notifications; Weak collections cannot be enumerated. `useDeepSignalValue` returns primitive snapshots only.
- Cross-copy readable Signals interoperate, but cross-copy batch operations are not a single atomic transaction; cross-generation Signal reactivity from v0.1.x is unsupported.
- React restarts a concurrent render synchronously when a Signal it read changed while the render yielded, so that render commits no mixed snapshot. The guarantee covers what each component tracked: `useSignalTracking()` collects only its own render window, which closes in a microtask (a yield included), so a descendant that reads Signals needs its own tracking call, as the [Hook guide](../guides/hooks.md#tracking-boundary) describes.
- Fast Refresh preserves Hook state. An omitted-dependency `useComputed` is backed by `useMemo`, so Fast Refresh may recreate the computed and apply edited getters/setters while preserving component state. See the [Hook guide](../guides/hooks.md#usecomputed).
