# v0.3.0 Release Notes — Draft

> **Unreleased draft.** Version `0.3.0` is the repository version, but it has not been published to npm. No release date or GitHub Release exists yet.

For upgrade steps from v0.2.1, see the [v0.3 migration guide](../migration/v0.3.md).

## Highlights

- Fine-grained React 19 rendering with Core Signals, React Hooks, and an opt-in JSX runtime.
- Reactive `Map`, `Set`, `WeakMap`, and `WeakSet` support in `deepSignal`.
- A managed build transform with explicit tracking diagnostics and Vite, Rollup, Webpack, Rspack, and esbuild integrations.
- Full and Lite JSX runtimes, so consumers can choose the supported binding contract they need.

## Added

- Writable `computed({ get, set })` and `useComputed({ get, set })` values, with writable capability represented in TypeScript.
- Explicit `bindValue` / `bindChecked` form bindings, including text, number and range inputs, textarea, select, radio and checkbox groups, native event ordering, reset, SSR/hydration, and IME handling.
- Full JSX host bindings for the documented attribute/style allowlist and Signal children.
- An opt-in `react-fine-grained-signals/lite` JSX runtime that supports ordinary JSX and Signal children without Full's attribute, style, or form binding implementation.
- `Match` value comparisons with `equals`, `useDeepSignalValue` selectors with optional dependencies, and `For` / `Index` control-flow utilities.
- Managed Transform diagnostics `RFGS001`–`RFGS009` and opt-in `diagnostics.errorOn` build errors.

## Changed / Breaking Changes

- Same-realm standard collections inside `deepSignal` are reactive by default; v0.2.1 read-only collection views and the old collection opt-in are removed. Values accessed through the proxy have reactive proxy identity, and mutations through raw references or `.peek()` do not notify.
- Signal-valued `value` / `checked` are no longer implicit JSX direct bindings. Use React controlled props with `.value` and `onChange`, or the explicit writable `bindValue` / `bindChecked` props under Full JSX.
- Managed Transform replaces v0.2.1's whole-function ambient collection with a top-level capture Hook and statically proven synchronous per-read capture. Review helper, alias, callback, and asynchronous read boundaries in the migration guide.
- The package is ESM-only, requires React 19 or newer, and requires Node.js 22 or newer for the runtime package. The optional transform package requires Node.js `^22.18.0 || >=24.11.0` because of Babel 8.

## Fixed / Hardened

- Invalid `useComputed` dependency mode, dependency length, and readonly/writable capability changes fail clearly instead of keeping stale memoized closures. `useSignalEffect` also rejects dependency length changes; omitted dependencies and `[]` remain equivalent for that Hook.
- Signal updates in `Switch` / `Match` can be tracked within the switch boundary using `Match equals`, without making the parent subscribe to the condition.
- The current implementation includes the M18.22 Core node construction reduction described below.

## Performance / Bundle

- In the M18.22 Node v24.21.0 Windows x64 measurement, eliminating the temporary node `fields` object reduced GC-retained heap by about 8 bytes per object when 50,000 Signal, readonly computed, or writable computed objects were retained. CPU time did not show a reliable improvement. This is a workload-specific memory measurement, not a per-application performance guarantee.
- The same exact bundle check measured `index-full` gzip at 24,672 bytes after the change, versus 24,697 bytes at its M18.21 baseline; all existing budgets remained unchanged. Bundle output depends on the consumer and toolchain.
- Lite reduced gzip size by 6,029 bytes versus Full in the M18.17 small production Consumer fixture. Importing Full and Lite together can erase or reverse that saving; this is not a fixed package-size guarantee. See the [JSX guide](../guides/jsx-bindings.md#setup).

## Known Limitations

- Managed capture is limited to statically analyzable synchronous reads. `mode: "auto"` does not select a caller solely because an imported helper reads a Signal; `transform: "inject"` and hand-written `useSignalTracking()` provide best-effort ambient tracking. Use an explicit `useManagedSignals()` lexical boundary when required.
- Full JSX direct binding is deliberately limited to documented native host elements and props. Lite supports Signal children only. Neither runtime unwraps Signals passed as React component props.
- `deepSignal` supports same-realm standard collections. Raw references and `.peek()` bypass reactive notifications; Weak collections cannot be enumerated. `useDeepSignalValue` returns primitive snapshots only.
- Cross-copy readable Signals interoperate, but cross-copy batch operations are not a single atomic transaction; cross-generation Signal reactivity from v0.1.x is unsupported.
- This is a draft pending release approval and the separate publication workflow. npm publish, version changes, tags, and GitHub Release creation have not occurred.
