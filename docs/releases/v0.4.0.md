# v0.4.0 Release Notes

For upgrade steps from v0.3, see the [v0.4 migration guide](../migration/v0.4.md).

v0.4.0 is a breaking release. It removes the code kept only for compatibility and narrows the public contract; its new APIs are `deepCollectionSignal` (with `useDeepCollectionSignal`), `useWritableComputed`, and the `Truthy` and `DeepReadonly` types. Before the release, functions that did the same job by different rules were made to share one implementation; the [migration guide](../migration/v0.4.md#consistency-fixes-before-the-release) lists what changed.

## Highlights

- One copy of the package: the cross-copy interop protocol is gone, and a mix of copies throws a clear error. The core is smaller (`signal` alone is about 1.7 kB gzip smaller).
- Clearer entry points: the classic `createElement` and the JSX runtimes live under `react-fine-grained-signals/jsx` and `/jsx/lite`, and the plugin's generated-code entry is `/internal`.
- `deepSignal` tracks plain objects and arrays only; Map, Set, WeakMap and WeakSet tracking moves to `deepCollectionSignal`. `deepSignal` and its hooks are about 4.3 kB gzip smaller than in v0.3 (14.59 to 10.33 kB).
- Tighter types: nominal `Signal` / `ReadonlySignal`, `FormBindableSignal` merged into `Signal`, `Truthy<T>` for `Show` / `Match` (the `MatchProps` export is removed), and a deep read-only `peek()`.

## Breaking Changes

- Loaded copies of the package no longer interoperate. Reading another copy's signal from an `effect`, `computed` or tracked component, and `isSignal` on another copy's signal, throw `Multiple copies of react-fine-grained-signals are loaded`. Install a single copy.
- Entry points: `createElement` is exported from `react-fine-grained-signals/jsx` instead of the root; `jsx-runtime` and `jsx-dev-runtime` moved to `jsx/jsx-runtime` and `jsx/jsx-dev-runtime`; `lite` and its runtimes moved to `jsx/lite`; `runtime` became `internal` and is outside semver. The old entries are removed without aliases. Set `jsxImportSource` to `react-fine-grained-signals/jsx` (or `/jsx/lite`).
- `useManagedSignals` and `ManagedSignalsStore` are removed. `useSignalTracking()` is the only tracking boundary you write yourself; the plugin no longer recognizes a hand-written managed boundary.
- Omitting a Hook dependency array means `[]` in `useComputed`, `useDeepSignalValue` and `useSignalEffect`. `useComputed` takes a getter only; use the new `useWritableComputed({ get, set })` for a writable computed.
- React `>=19.3.0` is required.
- `Show` and `Match` pass `Truthy<T>` to a function child.
- `FormBindableSignal` is removed; `Signal<T>` is the binding type. `Signal` and `ReadonlySignal` are nominal and `Signal<T>` is invariant in `T`.
- `deepSignal(...).peek()` is typed `DeepReadonly<T>`, and `DeepSignal<T>` is no longer a `Signal<T>`.
- `Map`, `Set`, `WeakMap` and `WeakSet` are untracked values inside `deepSignal`; a collection root is rejected. Use `deepCollectionSignal`.
- Plugin: `reactCompiler: "auto"` is renamed to `"opt-out"` (still the default, same behavior). An unknown `reactCompiler` value throws when the plugin is created.
- Plugin: every entry exports only the documented API. `pluginName`, `canTransform`, `resolveEsbuildLoader`, `createBundlerPlugin`, `EsbuildLoaderName` and `BundlerTransformOutput` are no longer exported.
- `useSignalValue` throws a `TypeError` during render for a value that is not a signal or computed from this package, instead of subscribing to it through an effect. The JSX bindings dropped the same fallback.
- The dependency-length errors of `useComputed`, `useWritableComputed`, `useDeepSignalValue` and `useSignalEffect` share one message format; their `error.name`s are unchanged.
- The Full and Lite JSX runtimes share one Signal-prop rule: on a custom element an unbound Signal prop, `value` and `checked` included, is passed through; Lite throws only where Full binds, and treats an `undefined` binding prop as absent.
- `useDeepSignalValue` throws a `TypeError` during render for a source that is not a `deepSignal` or `deepCollectionSignal`, plain signals included.
- Errors from `deepCollectionSignal` state name `deepCollectionSignal()`.
- Plugin: every option is validated when the plugin is created; diagnostics start with `[unplugin-react-fine-grained-signals]`; a component or custom Hook that reads signals only inside a callback passed to a Hook is no longer transformed.
- Plugin: reads inside async functions are never render dependencies, before the first `await` included; parameter defaults that may read through a call are moved into the body; `.mjsx`/`.mtsx` are no longer transformed.
- Plugin: auto mode selects a function exactly when the managed pass would capture one of its render reads, checked by a test over about 100 read shapes; reads only in uncalled local functions, stored handlers, timers, Promise callbacks or `untracked(...)` no longer select it.
- Plugin: optional chains are captured as a whole, so `a?.b().c` no longer throws when `a` is nullish; destructuring assignments, assignment-form loop heads and expression bases are captured; a signal read in a JSX tag name reports the new RFGS010 instead of being tracked; Hook names follow React's `use[A-Z0-9]` rule; RFGS009 is reported for components only and each diagnostic once per location. The selection and runtime-comparison tests now cover 29 deep-signal alias shapes.

## Added

- `deepCollectionSignal` and `useDeepCollectionSignal`, with the `DeepCollectionSignal` type. `useDeepSignalValue` accepts both kinds of deep signal.
- `useWritableComputed`.
- The direct-binding props (`title`, `id`, `className`, `hidden`, `disabled`, `style`, `aria-*`, `data-*`) also work on SVG and MathML hosts, written as attributes. The full JSX runtime no longer carries a list of SVG and MathML tag names.
- `Truthy<T>` and `DeepReadonly<T>` types.
- `For`, `Index`, `Show` and `Match` accept a `deepSignal` or `deepCollectionSignal` directly and type items by the signal's `.value` type, so a row can write through the item.
- Plugin: `include` and `exclude` also accept a `RegExp` or an array of predicates and `RegExp`s (`ReactFineGrainedSignalsFilterPattern`). Strings throw when the plugin is created; an empty `include: []` matches nothing.

## Fixed

- `useDeepSignalValue` no longer subscribes an effect that renders synchronously to its selector's reads.
- Deep arrays' `includes`/`indexOf`/`lastIndexOf` find a stored object holding a deep proxy, as `Set.has` does; a deep proxy inside a collection from another realm is rejected in `deepSignal`; property-metadata cleanup revisits the keys its first chunk deferred, as collection cleanup does.
- A throwing listener of a `useSignalTracking()` store no longer stops the listeners after it.
- An effect disposed during its first run (for example a child whose body disposes its owner) runs its cleanup and drops the subscriptions it made, as a re-run already did.
- Plugin: with `reactImportSource` set, calls to functions imported directly from `"react"` are no longer wrapped in `capture()`.
- Plugin: invalid output for `(x.value satisfies T) = v` and wrapped `++`/`+=`; `use()` inside a captured helper; false RFGS003 for a `Match` under a fragment in `Switch` and for async form actions; false RFGS004 for `.current.value` / `.target.value` defaults.

## Removed

- The ReadableInterop protocol and the foreign-copy bridge nodes in the core, and the v0.1.x mixed-version check.
- The Managed Transform's experimental per-read capture option (it was never reachable from the public plugin options).

## Notes

- Sizes (gzip, from `pnpm size`): `signal` only 6.09 to 4.38 kB; `deepSignal` with its hooks 14.59 to 10.33 kB; the main entry as a whole 24.88 to 15.74 kB (the JSX `createElement` left the root and `deepCollectionSignal` joined it). `deepCollectionSignal` with its hooks is 13.29 kB, about 1.3 kB smaller than v0.3's all-in `deepSignal`, and about 3.0 kB more than the plain-object `deepSignal`.
- Detecting two loaded copies has limits: a plain read outside any `effect`, `computed` or tracked component cannot be detected, and only v0.4 and later copies are detected (the brand and shared-context keys changed in v0.4, without the `.v2` generation suffix, and stay fixed from now on).
- Mutating a nested `Map` or `Set` inside `deepSignal` compiles but is not notified; search for those calls when upgrading.
- Use the runtime and `unplugin-react-fine-grained-signals` at the same `0.4.x`.
