# M1.2-0 — Reference Architecture Study

## Scope and starting state

This is a read-only architecture study for M1.2-0. It compares the current accepted RFSG representation with two frozen Alien-derived references and uses the completed M1.1b causal records. It proposes designs for a later prototype milestone; it does not implement them.

Verified starting state: local `main` and `origin/main` were both `3c6c627d8ceb20ab3f8b5f31c41a2b330c785fc5` (`docs: close Phase 9 M1.1b attribution`), and the working tree was clean. The runtime source baseline remains `c5d1796cfa2063db7eecb99e537209de185a530c`; no runtime-baseline input changed since it was frozen. The study inspected the current runtime, public API, interop, React tracking, JSX binding, deepSignal engine, and M1.1b attribution record.

## M1.1b context

Authoritative M1b current/v0.1.1 ratios include source/create `0.198`, source/read `0.698`, source/write-read `0.751`, computed/create `0.581`, computed/dirty-read `0.654`, computed/equality `0.781`, and effect/fanout at 16 and 64 of `0.826` and `0.721`. M1.1b diagnostic ablations then found repeatable creation work in `nodesByReadable.set` and the combined public brand/WeakSet registration; the tested source-read fast path and source revision-bump removal did not explain read/write-read results. Eager computed protocol construction did not explain computed creation. Graph scope contributed to computed dirty-read, revision settlement contributed somewhat to equality suppression, and graph/render scopes added repeated effect callback work. Corrected deepSignal retained-heap diagnostics closed the earlier large result as a measurement artifact.

These ablations intentionally removed semantics and are causal evidence that work occurs, not safe patches or additive shares of the M1b gap. Source read/write and most computed costs remain unpartitioned. See the immutable detail and raw records in [`benchmarks/phase9/attribution/README.md`](../benchmarks/phase9/attribution/README.md).

## Alien Signals 3.2.1 high-level

Alien high-level is a compact API over its own `alien-signals/system`. A source is a node object with the five principal own fields `currentValue`, `pendingValue`, `subs`, `subsTail`, and `flags`; the public callable is `signalOper.bind(node)`. Thus public signal identity is a bound function that closes over the graph node: it is near `public value ≈ node`, but not literally the same object and still allocates the callable. The callable handles zero arguments as read and one argument as write.

A computed node holds `value`, `getter`, `deps`, `depsTail`, `subs`, `subsTail`, and `flags`, and is exposed as `computedOper.bind(node)`. It evaluates lazily, tracks dependencies with the same linked graph, checks dirty dependencies before reevaluation, and propagates only when its result changes. An effect node stores callback/cleanup and graph fields; its returned bound disposer is another function allocation. Effects run immediately, clean up before reruns, and unlink their dependencies on disposal.

Each dependency edge is one `Link` object connected in both the dependency's subscriber chain and the subscriber's dependency chain. Notifications use module-level batch/run state and a reusable queue; stack records are created at branching graph-check points. The graph does not need per-edge Sets or Maps. The high-level API is a structural reference for an integrated public/node representation, not a production replacement for RFSG's required `alien-signals/system` boundary.

## Vue 3.6 reference

Vue's pinned `system.ts` is explicitly ported from Alien Signals. `ReactiveNode` carries optional `deps`, `depsTail`, `subs`, `subsTail` and a `flags` word. A single seven-field `Link` (`version`, `dep`, `sub`, and four adjacent-link pointers) participates in both directions. `link()` reuses the current tail edge when possible; tracking advances a global version, and the end of tracking unlinks stale dependencies. Effects, computed values, refs, and effect scopes reuse this graph.

`RefImpl` directly implements `ReactiveNode`: its `.value` getter tracks `this`, settles dirty state, and returns its stored value; its setter applies Vue's raw/wrapped value rules and propagates through `this.subs`. A `dep` compatibility getter returns `this`. The source has no ref-to-node lookup. It carries value/wrapping state and Vue ref/shallow flags in addition to graph fields. `ComputedRefImpl` also directly implements `ReactiveNode`, with both dependency and subscriber lists, dirty/pending flags, a lazy getter/cache, and equality-aware propagation. It keeps `.dep`, `.effect`, and `_dirty` compatibility accessors plus dev-only debugger hooks. `ReactiveEffect` is itself the graph subscriber and owns cleanup/debug state; the runner returned by the API is a callable with an `.effect` reference.

Vue's `targetMap: WeakMap<object, Map<PropertyKey, Dep>>` solves a different mapping problem: proxy property reads need a stable dependency for each target/key pair. `Dep` is not needed to map a ref to its own graph node. It prunes itself from the target's inner map when the final subscriber unlinks. Proxy identity has separate weak maps. `EffectScope` also implements `ReactiveNode`; links model scope ownership, enabling scoped stop/cleanup without a separate effect membership Set. Runtime globals (active subscriber, batch/run depth, version, notify buffer, active scope) are module-local and assume one module instance; they do not supply RFSG's duplicate-copy protocol.

Vue is a production-grade example of direct node identity, but its Vue ref unwrapping, proxy tracking, compatibility surface, debugger hooks, SSR behavior, and singleton state differ from RFSG's React/cross-copy contracts. Its representation is precedent, not a drop-in design.

## RFSG current representation

Public `signal()` and `computed()` call the runtime factory and then `registerSignal()`. Each readable has a public `RuntimeSignalReadable` or `RuntimeComputedReadable` wrapper holding a private `#node`, plus a separate `SignalNode` or `ComputedNode`. `nodesByReadable` maps that wrapper back to its node for runtime helpers such as subscriber queries and deepSignal integration. The wrapper attaches a nonenumerable `READABLE_INTEROP_V1` symbol property whose value is a separate frozen protocol object with two closures (`getRevision`, `subscribe`). Public registration adds a `WeakSet` entry and defines a nonenumerable global-symbol brand. This is two objects per public readable, a WeakMap entry, a protocol object, two protocol closures, a symbol property, a WeakSet entry, and a symbol brand property, in addition to the node's fields and shared/prototype methods.

RFSG nodes carry the Alien graph fields plus a kind, runtime token, and rendering/protocol support. Source nodes eagerly hold `currentValue`, `pendingValue`, revision, and four nullable listener/watcher slots. Computeds eagerly hold getter, lazy value/error state, render-observed snapshot state, speculative cache/dependency state, foreign-dependency/liveness booleans, revision, and the same listener/watcher slots. The slots begin `undefined`; the corresponding Sets/watchers are created when subscribed. Each runtime is created once through `coreRuntime` and owns runtime-local state including `nodesByReadable`, its graph token, notification state, and watcher sets.

Effects are direct runtime nodes, not public readable wrappers. They store callback, cleanup, active/running/scheduled flags, and graph links. Each run nests interop speculative isolation, foreign graph capture, and render-collection isolation; errors are contained and reported, synchronous effects clean up before rerun, and disposal unlinks dependencies. This is required work when the relevant feature is active, but M1.1b shows that no-op scopes can be measurable in fan-out workloads.

React's `RenderStore` tracks committed and pending render dependencies and listeners per hook instance. Nodes expose render revision/subscription behavior; render watchers and listener Sets are subscription-only allocations. Speculative computed reads maintain temporary dependencies/results and promote only after validation. Foreign dependencies are represented by per-runtime external nodes and subscribe only while live. JSX direct binding uses the readable protocol when available, with an effect bridge fallback. `deepSignal` adds its own wrapper, proxies and lazily created object/property metadata; its proxy/property Maps, Sets, WeakMaps and version sources answer property-level tracking needs rather than ordinary source identity.

## Source representation analysis

The preliminary models are useful but need precision:

- **Alien:** public source is a bound function over a compact node, not the node itself. The bound function is a real extra allocation. This supports direct identity as a candidate, but does not prove all APIs can be merged without preserving an operation function or public properties.
- **Vue:** `RefImpl` is simultaneously the public ref and source `ReactiveNode`; `get dep()` returns `this`. No ref-to-node lookup exists. Vue's proxy `targetMap` is for target/property dependencies, not refs.
- **RFSG:** the wrapper → `nodesByReadable` → node picture is accurate for runtime lookup, but incomplete: the wrapper also owns public accessors and a symbol property pointing to a separate protocol object; node state participates in render tracking, deepSignal identification, and cross-copy subscription. The `WeakMap` is only removable if all such consumers can resolve the node directly or use an explicit feature-specific route.

M1.1b shows creation time in map insertion (2.025 variant/control throughput ratio, wide spread) and combined public registration (1.428, 4/4 directions), with a smaller and less repeatable eager protocol result (1.160). These removal variants break supported behavior and are not additive. The data establishes a strong reason to prototype integrated identity; it does not assign all `0.198` source/create regression to those layers.

`public signal object == SignalNode` can preserve `.value`, `peek()`, local graph fields, and `hasSubscribers` without a reverse map, if methods/accessors and kind identity are safe across public APIs. It raises object-shape and exposure questions: graph fields become public own properties unless hidden by private fields/prototype accessors, and shared symbol/protocol properties need collision-safe definitions. DeepSignal can use an internal direct-node capability or validated identity rather than querying a wrapper map. Render dependencies still need revision snapshots/subscriptions. Cross-copy readers should keep a narrow validated protocol and must not infer node internals from a foreign brand. GC can improve by removing a wrapper-map association, but a protocol closure that captures the node can still retain it for the public object's lifetime; this is appropriate only while the public readable is alive.

## Computed representation and hot/cold classification

| Current computed field/state | Classification | Per-instance necessity and candidate treatment |
| --- | --- | --- |
| `getter`, `initialized`, `hasError`, `value`, `error`, `deps/depsTail`, `subs/subsTail`, `flags` | Core hot/correctness | Needed for lazy cache/error semantics and Alien graph relations. Error fields could use a compact tagged cache only after measuring and verifying thrown-`undefined` behavior. |
| `revision`, `observedInitialized`, `observedHasError`, `observedValue` | React/render only | Revision and observed snapshot support render consistency/equality settlement. Some snapshot state may be moved into nullable render feature state; the normal read must not gain an unconditional map lookup. |
| `renderListeners`, `renderWatcher` | Subscription-only / React | Null slots are eagerly present; Set and watcher are already lazy on first listener. A single nullable render sidecar could group them, at cost of a read/write branch or lookup when render revision state is accessed. |
| `protocolListeners`, `protocolWatcher` | Cross-copy interop / subscription-only | Null slots are eagerly present; listener Set/watcher are lazy. Could share a feature sidecar with render state but must keep foreign and React subscriptions independent. |
| `speculativeResult`, `speculativeDeps`, `speculativeCachePromotable` | Speculative render only | Needed only when render speculation reaches a computed. The result/map are null until used; a lazy sidecar can combine with render snapshot state if it does not create eager lookup tax. |
| `foreignDependent`, `live` | Cross-copy interop/liveness correctness | Needed when foreign graph dependencies exist. Currently booleans occupy every computed. Candidate for interop feature state, but liveness transitions must unsubscribe/re-subscribe correctly. |
| `kind`, `runtimeToken`, `interop` | Runtime/interoperability correctness | Runtime token and protocol are eagerly attached. Direct node identity could remove `nodesByReadable`; protocol may be prototype-shared or lazy while retaining version/runtime validation. |

The computed node is materially larger than Alien/Vue because it stores multiple correctness domains together, not because all fields are part of the local lazy computed algorithm. However, eager nullable slots avoid a map lookup on their feature paths and preserve stable object shape. A single lazy feature object may reduce base fields and group render, protocol, speculative, and foreign state, but it adds a branch/indirection when used. A `WeakMap` sidecar per computed would risk recreating the lookup cost under a new name. Prototype methods are preferable for shared behavior; per-instance state should remain directly addressable where it is hot.

M1.1b's computed ablations refine rather than settle this: graph-scope omission helped dirty/read (1.137) but not dirty/unread (0.996); skipping revision settlement helped equality (1.122) but not dirty/read (0.967); skipping eager protocol construction did not help creation (0.994). Therefore no computed fields are admitted for deletion. Candidate cold-state grouping needs its own semantics-preserving prototype and workload evidence.

## Identity and branding

RFSG currently uses local `WeakSet` authority plus a global symbol numeric version for cross-copy recognition. `isSignal()` accepts local instances quickly; for foreign values, the brand is a claim and `.peek` is checked before accepting. This is safer than Vue's simple structural ref flag for RFSG's broader readable contract and preserves the stated malformed-brand principle.

Possible lower-setup models are:

1. **Prototype identity:** cheap same-copy check with `instanceof`/prototype membership, but fails across realms/copies and can be changed by prototype manipulation. It is not a sufficient foreign identity contract.
2. **Own internal marker:** a version field or private local symbol can replace WeakSet insertion, but remains per-instance setup and can be forged unless paired with local prototype or private identity evidence.
3. **Shared symbol only:** keeps cross-copy identity but the brand remains only a claim; always validate the public readable shape and callable methods. This may reduce the WeakSet cost but can still incur symbol property creation.
4. **Private local identity plus shared validated fallback:** retain an authoritative local fast path and validate foreign branded values. This best preserves the current security model; whether prototype/field evidence is cheaper than WeakSet is unproven.
5. **Protocol as foreign evidence:** a validated interop protocol can establish runtime capability, but `isSignal()` promises public signal identity, while protocol presence may also belong to internal or future readable types. Keep these concepts separate unless the API contract explicitly equates them.

An integrated public node could use its own runtime token/kind locally and a shared symbol protocol for foreign detection. Do not blindly trust a foreign symbol or expose graph-node claims as proof. M1.1b measured WeakSet+brand registration as a combined contributor only; it did not isolate the operations.

## Interop representation strategies

| Strategy | Same-copy creation/read | Cross-copy semantics and validation | Receiver/shape/GC implications | Assessment |
| --- | --- | --- | --- | --- |
| 1. Current separate protocol | Eager per-readable frozen object, two closures, symbol lookup on foreign path; local creation pays setup. | Explicit `version`, `runtimeToken`, `getRevision`, `subscribe`; stable contract across duplicate package copies. | Closures capture node; frozen object prevents mutation; own symbol changes wrapper shape. | Lowest conceptual risk; M1.1b found only partial source-create contribution and no computed-create effect. |
| 2. Integrated protocol | Public/node object is the protocol target; shared prototype methods can avoid two closures and separate protocol allocation. Same-copy reads need not consult protocol. | `READABLE_INTEROP_V1` may resolve to `this`; validate version, token and methods. Methods must reject wrong receivers or be called with the readable as `this`. | No separate protocol object; symbol still present. | 3. Lazy protocol exposure | Ordinary source/computed creation omits protocol object/closures/property; create or attach when the first foreign consumer requests it. | First foreign access must safely negotiate and share capability; `getReadableInterop` cannot see an absent protocol until exposure. Per-readable protocol objects/closures can plausibly be eliminated if methods are shared and receiver-safe while preserving the versioned protocol. Lazy exposure can plausibly defer cost, but should be a competing prototype only if there is a clean cross-copy discovery mechanism. Do not remove the protocol contract or accept malformed protocol objects.

## Effect and scope comparison

Alien and Vue set a module-level active subscriber and graph links around effect execution, clean old dependencies, and restore tracking state. Vue additionally keeps run depth, a batch queue and effect scopes; these globals are cheap checks in the no-scope case. Neither reference has RFSG's React render collectors or duplicate-runtime graph protocol.

RFSG effect work classifies as follows:

| Work | Classification | Evidence / boundary |
| --- | --- | --- |
| Save/set/restore `activeSub`, linked graph tracking, stale dependency purge | Always required for local dynamic dependencies and cleanup | Preserve same-run tracking and exception-safe restoration. |
| `withTrackedGraph` | Required only when foreign graph capture is active; correctness path for cross-copy dependencies | M1.1b repeated omission effects at fanout 1 and 16; unguarded removal loses foreign dependencies. |
| `withoutAllRenderCollection` local/shared collector isolation | Required when callbacks run under a component collector | M1.1b repeated render-isolation work, especially at fanout 16/64. Must continue isolating shared and local collectors. |
| `activeRenderReads` and `speculativeReads` save/clear/restore | Required only if either render-read state is active | Later approved narrow guard may skip that portion only when both are `undefined`; not implemented or measured here. |
| interop speculative mode | Required only during duplicate-copy speculative boundaries | State is shared by symbol context; nested depth/epoch restoration is correctness behavior. |
| Error containment, synchronous execution, cleanup lifecycle | Required public behavior | Do not trade away for throughput. |

Vue's active-sub stack pattern offers a useful no-op-scope precedent, but RFSG's collector nesting and shared cross-copy context make its scopes non-equivalent. M1.2-0 does not implement the previously admitted guarded render-state optimization.

Prefer one direct nullable field over weak-map sidecars for the prototype comparison; retain ordinary graph fields directly on the node.

## Required RFSG invariants

Any M1.2-1 architecture must preserve:

- `alien-signals/system` as the production Alien boundary;
- public `signal`/`computed` APIs, `.value`, and `peek()`;
- `Object.is` equality, lazy computed evaluation, cached computed errors, and equality suppression;
- synchronous effects, cleanup before rerun/disposal, and effect error containment;
- `batch()` and `untracked()` behavior;
- React render tracking, revision/race safety, managed exact boundaries, and best-effort bare-boundary behavior;
- speculative render correctness and safe cache promotion;
- cross-copy readable interoperability and foreign readable/computed dependencies;
- deepSignal property/iteration semantics;
- dynamic dependency cleanup and subscription/disposal correctness.

Across candidates, the most likely source/create opportunity is A/B, while C is valuable as a lower-risk control. Source read/write potential remains structural rather than causal evidence; the tested guarded source-read path did not help. Computed dirty-read and fan-out improvements are not predicted from identity integration alone. GC may improve by dropping wrappers/maps but can regress if new sidecars or closures retain nodes; object-shape and bundle effects remain hypotheses until checked in a prototype. No hidden-class or byte-size claim is made here.

## M1.2-1 recommendation and explicit decisions

**Prototype Candidate A and Candidate C as competing first designs.** Alien's compact bound-node API and Vue's direct `RefImpl`/`ComputedRefImpl` provide structural precedent for public/node integration. M1.1b specifically identified wrapper-to-node registration and public identity setup as substantial source-creation work. RFSG's independent render, deepSignal, and duplicate-copy requirements mean this is not a direct port: Candidate A should retain a validated versioned protocol and preserve feature boundaries. Candidate C is the lower-risk control that tests whether protocol/identity construction can be reduced without changing the two-object representation. M1.1b did not show eager computed protocol setup as a computed-create cause, so do not prioritize a computed protocol-only experiment over the source identity prototypes.

Candidate B should follow only if A shows that the remaining computed allocation/state is material and a single direct nullable feature object can avoid normal-path lookup. Beginning with multiple WeakMap sidecars would risk reproducing the map cost. A and C should compare semantics first and only then use focused creation/read/fan-out diagnostics; no candidate has an assumed performance percentage.

**Should public signal/computed values remain wrappers around separate runtime nodes?** No as the only architecture: prototype an integrated public/node representation (A), while retaining C as a control because the semantic migration is substantial. Current evidence supports testing the split, not declaring it removable without validation.

**Can `nodesByReadable` be removed from the normal representation?** Plausibly yes if source/computed public identity becomes the node, and internal helpers receive/validate that object directly. This is the clearest design path to remove the reverse lookup. Do not recreate it as a differently named WeakMap sidecar. If wrappers remain, every consumer of node lookup (including deepSignal and subscriber queries) needs an explicit replacement first.

**Can per-readable protocol objects/closures be eliminated or made lazy?** Plausibly yes: shared prototype methods on an integrated object can implement the same validated protocol with receiver-safe calls and no node-capturing per-readable closures. Lazy protocol exposure is also plausible, but cross-copy first-use discovery and late object-shape changes make it a riskier second experiment. Protocol versioning, runtime token, revision and subscription behavior must remain.

## Non-goals

This study does not modify `src/**`, implement a prototype, run benchmarks, alter M1b/M1.1b data, change public APIs, redesign deepSignal, replace the production Alien boundary with Alien high-level, begin M2, or start any M1.2-1 work. It does not claim precise allocation bytes, additive cost shares, or V8 hidden-class effects.
