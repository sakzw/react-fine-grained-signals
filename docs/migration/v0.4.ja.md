# v0.4への移行

v0.4は、互換性のためだけに残していた部分を削り、公開契約を細くする破壊的リリースです。runtimeとbuild pluginは必ず同じ`0.4.x`に揃えて更新し、手元のコードに関係する節を読んでください。

| 領域 | v0.3 | v0.4 |
| --- | --- | --- |
| 読み込まれたpackageのcopy | copy同士が連携した | 1つだけinstallする。混在するとthrowする |
| classicな`createElement` | `react-fine-grained-signals` | `react-fine-grained-signals/jsx` |
| JSX import source | `react-fine-grained-signals` | `react-fine-grained-signals/jsx` |
| Liteのimport source | `react-fine-grained-signals/lite` | `react-fine-grained-signals/jsx/lite` |
| 生成コード用のentry | `react-fine-grained-signals/runtime` | `react-fine-grained-signals/internal`（公開APIではない） |
| 手書きの厳密な境界 | `useManagedSignals()` | 削除。plugin、leaf hook、`useSignalTracking()`を使う |
| 依存配列の省略と`[]` | `useComputed`と`useDeepSignalValue`では別のmode | どのHookでも同じ |
| 書き込み可能なcomputedのHook | `useComputed({ get, set })` | `useWritableComputed({ get, set })` |
| React | `>=19.0.0` | `>=19.3.0` |
| `Show`/`Match`のcallbackの値 | `NonNullable<T>` | `Truthy<T>` |
| 書き込み可能なsignalの型 | `FormBindableSignal<T>` | `Signal<T>` |
| `deepSignal(...).peek()` | `T` | `DeepReadonly<T>` |
| `deepSignal`の中の`Map`/`Set` | リアクティブ | 追跡しない。`deepCollectionSignal`を使う |

## packageのcopyは1つだけにする

v0.3では、読み込まれた複数の`react-fine-grained-signals`のcopyが、共有のprotocolを通じてリアクティブなreadをやり取りできました。v0.4ではこのprotocolを削除しました。すべてのsignal readが軽くなり、coreも小さくなります（`signal`だけを使う場合でgzipで約1.5 kB減）。

各copyは独自のグラフを持つため、2つ目のcopyは、更新されない値を黙って返すのではなくエラーになります。

- 別のcopyのsignalを`effect`、`computed`、追跡されるコンポーネントの内側から読むと、`Multiple copies of react-fine-grained-signals are loaded; install a single copy`をthrowします。
- `isSignal`は、別のcopyが作ったsignalに対してthrowします。
- `effect`、`computed`、追跡されるコンポーネントの外で行う単純なreadは検出できません。現在の値を返しますが、何も更新されません。

重複はinstall側で解消してください。package managerのdedupe（pnpmの`dedupe-peer-dependents`、`npm dedupe`）を実行するか、bundlerが1つのcopyに解決するようにします（ViteとRollupでは`resolve.dedupe: ["react-fine-grained-signals"]`）。独自のstoreを配布するpackageは、このライブラリをpeer dependencyとして宣言してください。v0.4の隣にv0.1.xのcopyがある状態は、従来どおり非対応です。

## entry point

ルートは`createElement`をexportしなくなり、JSX runtimeは`/jsx`の下へ移りました。旧entryはaliasを残さず削除したので、古いimportは解決エラーになります。

| 変更前 | 変更後 |
| --- | --- |
| `react-fine-grained-signals`（`createElement`） | `react-fine-grained-signals/jsx` |
| `react-fine-grained-signals/jsx-runtime` | `react-fine-grained-signals/jsx/jsx-runtime` |
| `react-fine-grained-signals/jsx-dev-runtime` | `react-fine-grained-signals/jsx/jsx-dev-runtime` |
| `react-fine-grained-signals/lite` | `react-fine-grained-signals/jsx/lite` |
| `react-fine-grained-signals/lite/jsx-runtime` | `react-fine-grained-signals/jsx/lite/jsx-runtime` |
| `react-fine-grained-signals/lite/jsx-dev-runtime` | `react-fine-grained-signals/jsx/lite/jsx-dev-runtime` |
| `react-fine-grained-signals/runtime` | `react-fine-grained-signals/internal` |

`/utils`は変更ありません。実際には、JSX import sourceを設定している箇所を書き換えます。

```json
{ "compilerOptions": { "jsx": "react-jsx", "jsxImportSource": "react-fine-grained-signals/jsx" } }
```

```tsx
/** @jsxImportSource react-fine-grained-signals/jsx */
```

Lite runtimeには`react-fine-grained-signals/jsx/lite`を使います。Viteの`react({ jsxImportSource })`オプションやbundlerのaliasも同様です。2つのJSX entryは、どちらも`createElement`、`Fragment`、`JSX`名前空間、`SignalChild`型をexportします。

`/internal`は、build pluginが生成するコードがimportするもの（`useSignalCapture`）を置く場所です。公開APIではなく、semverの対象外です。pluginに独自の`importSource` wrapperを渡している場合、そのwrapperは`/internal` entryから`useSignalCapture`をre-exportする必要があります（以前は`/runtime`）。pluginはruntimeと同じrelease lineのものを使ってください。

## `useManagedSignals`の削除

自分で書く追跡境界は`useSignalTracking()`だけになりました。`useManagedSignals`と`ManagedSignalsStore`はpackageのentryから削除され、pluginも手書きの`useManagedSignals()`境界を認識しません。`try` / `finally`の境界は、次のいずれかに置き換えてください。

- `transform: "managed"`（既定）のbuild plugin。静的に証明できる同期readをcaptureします。
- leaf hookの`useSignalValue`と`useComputed`。
- `useSignalTracking()`。[Hooksガイド](../guides/hooks.ja.md#追跡境界)のbest-effortの制約があります。buildでReact Compilerを使う場合、手書きの`useSignalTracking()`のコンポーネントには`"use no memo"`が必要です。

## Hookの依存配列

`useComputed`、`useDeepSignalValue`、`useSignalEffect`のどれでも、依存配列の省略は`[]`と同じ意味になりました。省略と`[]`の切り替えはエラーになりません。長さの変更は引き続きthrowし、省略（または`[]`）と空でない配列との切り替えは「長さの変更」として報告されます。`UseComputedModeChangeError`と`UseDeepSignalValueModeChangeError`はなくなりました。

`useComputed({ get, set })`は`useWritableComputed({ get, set }, deps?)`に移りました。`useComputed`はgetterだけを受け付けるため、実行時の読み取り専用／書き込み可能のcapabilityチェックは不要になり、削除しました。プリミティブの`computed({ get, set })`は変わりません。

## React 19.3

peer dependencyは`react >=19.3.0`です。React 19.3は、`<Activity>`が隠れている間のstore変更を`useSyncExternalStore`が見落とす不具合を修正しており、ライブラリのテストはその挙動を前提にしています。React 19.0〜19.2は非対応になりました。

## TypeScriptの変更

- **`Signal`と`ReadonlySignal`は名目的な型です。** `value`と`peek()`だけを持つオブジェクトは`ReadonlySignal`ではありません（`isSignal`と同じ判定です）。構造的なreadableを`useSignalValue`に渡すにはキャストが要ります。`ReadonlySignal<T>`は`T`について共変のままです。
- **`Signal<T>`は`T`について不変です。** `Signal<"a" | "b">`を`Signal<string>`が期待される場所には渡せません。選択肢型のbinding（radio、select、checkbox group）は、リテラルunionのsignalを引き続き受け付けます。
- **`FormBindableSignal`は削除**しました（aliasなし）。`Signal`に置き換えてください。`signal()`、`useSignal()`、`useWritableComputed()`、`computed({ get, set })`は`Signal<T>`を返すので、変数を`Signal<T>`と注釈してもbinding capabilityは失われません。
- **`Show`と`Match`**は、関数childに`Truthy<T>`を渡します。`Truthy<T>`は`T`から`null`、`undefined`、`false`、`0`、`""`、`0n`を取り除いた型です（`/utils`からexportされます）。exportされていた`MatchProps`型は削除しました（`Match`のoverloadがすでに表している型なので）。`Match`要素の型は`Match`自体を通して付けてください。
- **`deepSignal(...).peek()`は`DeepReadonly<T>`を返します。** objectのpropertyは`readonly`、配列は`ReadonlyArray`、`Map`と`Set`は`ReadonlyMap`と`ReadonlySet`になり、`WeakMap`と`WeakSet`からは`set`、`add`、`delete`が取り除かれます。`peek()`経由の書き込みはコンパイルエラーです。変更は`.value`経由で行ってください。実行時の`peek()`は引き続き生のオブジェクトを返します。
- **`DeepSignal<T>`は`Signal<T>`ではなくなりました。** `Signal<T>`が期待される場所に渡していたコードは、`.value`経由で読むように直す必要があります。plain objectのルートなら、構造的には`ReadonlySignal<T>`に代入できますが、配列とcollectionのルートは代入できません。

## collectionは`deepCollectionSignal`へ

`deepSignal`はplain objectと配列だけを追跡するようになり、`Map`や`Set`を入れないアプリはcollection対応のコードを読み込まなくなりました（`deepSignal`とそのHookでgzipで約2.7 kB減）。deep signalに`Map`、`Set`、`WeakMap`、`WeakSet`を入れている場合は、`deepCollectionSignal`（と`useDeepCollectionSignal`）に切り替えてください。

```ts
import { deepCollectionSignal } from "react-fine-grained-signals";

const state = deepCollectionSignal({ tags: new Set<string>(), counts: new Map<string, number>() });
state.value.tags.add("react");
```

`deepSignal`での変更点は次のとおりです。

- `Map`、`Set`、`WeakMap`、`WeakSet`をルートにすると型エラーになり、`deepCollectionSignal`を案内する`TypeError`をthrowします。
- ネストしたcollectionは、`Date`と同じ追跡しない値です。identityは保たれ、signalが通知するのは、それを保持するプロパティに別の値が代入されたときだけです。`state.value.tags.add(x)`は**通知されず**、型の上では呼び出せてしまうので、upgradeの際にこうした変更を検索してください。
- plain objectや配列を、`deepSignal`と`deepCollectionSignal`の間で共有することはできません。同じ生のオブジェクトを両方でラップしたり、片方のproxyをもう片方に代入したりするとthrowします。

`useDeepSignalValue`はどちらの種類も受け付けます。`DeepCollectionSignal<T>`と`DeepSignal<T>`は別の型です。

## チェックリスト

1. ライブラリのcopyを1つにする。package managerのdedupeを実行する。
2. `jsxImportSource`、pragma、bundlerのaliasを`/jsx`のentryに更新する。
3. `useManagedSignals`の境界を置き換える。`useComputed({ get, set })`を`useWritableComputed`に変える。
4. `Map`/`Set`の状態を`deepCollectionSignal`に移し、`deepSignal`の中のネストしたcollectionの変更を探す。
5. `FormBindableSignal`を`Signal`に置き換え、共変を前提にした`Signal<T>`の代入を直す。
6. Reactを19.3以降にする。
7. pluginを同じ`0.4.x`に更新する。
