# v0.2への移行

このガイドでは、v0.1.1からv0.2へ更新するときの公開APIとdependencyの変更点を説明します。

## 描画追跡フック

v0.1.1には、同じ名前の異なるhookが2つありました。import pathごとに追跡契約が異なるため、それぞれ分けて移行してください。

### root API: bare / best-effort追跡

rootの `useSignals()` はrootの `useSignalTracking()` に変わりました。

```tsx
// v0.1.1
import { useSignals } from "react-fine-grained-signals";
```

```tsx
// v0.2
import { useSignalTracking } from "react-fine-grained-signals";

function Counter() {
  useSignalTracking();
  // 描画中にsignalを読み取ります。
}
```

これは小さなbest-effort追跡境界です。

### `/runtime` API: managed / exact追跡

別APIである `/runtime` の `useSignals()` aliasは、`/runtime` の `useManagedSignals()` に変わりました。

```tsx
// v0.1.1
import { useSignals } from "react-fine-grained-signals/runtime";
```

```tsx
// v0.2
import { useManagedSignals } from "react-fine-grained-signals/runtime";

function Counter() {
  const scope = useManagedSignals();
  try {
    return <output>{count.value}</output>;
  } finally {
    scope.finish();
  }
}
```

これはmanaged / exactな描画追跡境界です。transform pluginを利用できる場合は、既定の `transform: "managed"` が推奨される正確な追跡境界であり、この `try/finally` scopeを自動挿入します。手動の `useManagedSignals()` はpluginを使わない場合の選択肢です。高度な `transform: "inject"` modeでは、代わりにrootのbest-effort境界 `useSignalTracking()` が挿入されます。

## Managed scopeのmethod

`ManagedSignalsStore.f()` は削除されました。`scope.f()` を `scope.finish()` に置き換えてください。

## Alien Signals dependency

`alien-signals` はRFSGのpeer dependencyから通常のdependencyに変わり、RFSGが低レベルの `alien-signals/system` moduleの上に構築されているため、正確なversion(`3.2.1`)に固定されています。v0.1.1のpeer dependencyを満たすためだけにアプリへ直接追加していた場合は、その直接dependencyを削除できます。アプリ自身がAlien Signalsをimportしている場合は、アプリのdependencyとして残してください。アプリ側のcopyとRFSG側のcopyが同じversionである必要はありません。

## v0.1.xとv0.2の混在

RFSGを同梱または依存しているpackageは、まとめてupgradeしてください。v0.2のsignalは新しい識別brandを使うため、v0.1.xのcopyはそれをsignalとして認識せず、v0.2もv0.1.xのsignalを認識しません。一方の世代のsignalをもう一方のJSXで描画すると、更新されない値を描画するのではなく、明示的に失敗します(Reactがobjectの子要素として報告します)。effectやhooksを通じて世代間でsignalを受け渡しても反応せず、サポート対象外です。同じページに複数のv0.2のcopyがある場合は、引き続き相互に連携します。

## Effect

ネストしたeffectはv0.1.1と同じ挙動のままです。別のeffectの実行中に作られたeffectは、そのeffectの再実行時または解除時に解除されます。`untracked()` は、インストールされたRFSGの別のcopyによる追跡も抑止するようになりました。

## deepSignalの追跡

- 配列の変更メソッドは、呼び出したコードを購読させなくなりました。配列へ `push` するeffectが、その配列への以後の `push` のたびに再実行されることはありません。
- `Object.keys`、`for...in`、`Object.hasOwn`、`hasOwnProperty.call` は、プロパティの値の変化ではなく、keyの追加と削除で再実行されます。`Object.getOwnPropertyDescriptor(...).value` だけを通じた値の読み取りは追跡されなくなったため、プロパティそのものを読んでください。
- `Object.prototype` から継承したkey(`constructor`、`toString` など)は、辞書的なオブジェクトでリアクティブになります。
- deep proxyを継承したオブジェクトを通じた書き込み(`Object.create(state.value).x = 1`)は、通常の代入と同じくそのオブジェクトにプロパティを定義し、deepな状態は変更しません。

## JSXとhooks

- host propは、要素やその子を再マウントせずに素の値とsignalを切り替えられます。bindingされたhost要素は内部コンポーネントで包まれなくなり、bindingは要素のrefを通じて付けられます。自分で渡した `ref` も引き続き要素を受け取ります。
- bindingした `value`/`checked` はformのresetの後も保たれます。`form.reset()` や `<form action>` 実行後のReact 19のresetは、signalの現在値に戻します。fieldを空にしたい場合はsignalへ書き込んでください。
- `useSignalValue()`、signal子要素、bindingするhost propは、rootの置き換えしか追わないため、TypeScript上で `deepSignal` を受け付けなくなりました。`useDeepSignalValue()` を使うか、追跡されたコンポーネント内でdeepな状態を読んでください。
- package rootが `createElement` をexportするようになりました。これは `jsxImportSource` の下で `<div {...props} key="k" />` を書いたときにcompilerがフォールバックする従来型のfactoryで、直接呼ぶためのものではありません。
- bareな `useSignalTracking()` のウィンドウは、Reactがコミットを始めた時点で閉じるようになったため、子孫のlayout effectやref callbackがそのウィンドウに紐付くことはなくなりました。
