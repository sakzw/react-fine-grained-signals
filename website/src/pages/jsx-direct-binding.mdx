# JSX Direct Binding

The package's JSX runtime lets a signal passed to a **native** element update
that DOM node on its own, without re-rendering the component around it.

```tsx
/** @jsxImportSource react-fine-grained-signals */
import { signal } from 'react-fine-grained-signals'

const title = signal('Initial title')

export function Heading() {
  return <h1>{title}</h1>
}
```

## Setup

Per file, with a pragma on the first line (every other file keeps React's
runtime):

```tsx
/** @jsxImportSource react-fine-grained-signals */
```

or project-wide in `tsconfig.json` with
`"jsxImportSource": "react-fine-grained-signals"`. Vite reads both. Builds that
compile JSX with Babel name the runtime on `@babel/preset-react` instead.

For an explicit Signal-children-only runtime, use
`"jsxImportSource": "react-fine-grained-signals/lite"`. Lite keeps ordinary
React JSX and fine-grained Signal children, but omits direct attribute and form
bindings. TypeScript rejects those binding props, and runtime checks report
unsupported Signal-valued host props passed from JavaScript or spreads. Use the
default package source when direct bindings are needed.

## What is bound

- **Signal children** of native elements, including SVG text content.
- **Props**: `title`, `id`, `className`, `hidden`, `disabled`, `data-*`, and
  `aria-*`.
- **`style`**, as a whole signal or with signal-valued entries
  (`style={{ color: colorSignal }}`).
- **Form fields** through `bindValue` and `bindChecked` (below).

Signals passed to React **components** are not unwrapped, and elements whose
children React handles specially (`<title>`, `<textarea>`, `<style>`) do not
take signal children.

## Form bindings

`value` and `checked` keep React's controlled-input behavior. For direct
synchronization, use the explicit binding props with a writable signal:

```tsx
const amountString = signal('')
<input bindValue={name} />
<input type="number" step="any" bindValue={amountString} />
<input type="range" min="0" max="100" step="1" bindValue={levelString} />
<input type="checkbox" bindChecked={subscribed} />
<input type="radio" name="plan" value="basic" bindValue={plan} />
<input type="checkbox" name="features" value="search" bindValue={features} />
<select bindValue={selected}>…</select>
```

- Text-like, number, and range inputs, `textarea`, single and `multiple` selects, radio groups, and
  checkbox groups are supported.
- `type="number"` uses a string signal. The empty value is `""`; browser
  sanitization and `min`/`max`/`step` validity remain native.
- `type="range"` also uses a string signal. RFSG does not parse `valueAsNumber`
  or implement min/max/step correction; the browser owns range-control semantics.
- Radios in one native group must share one signal.
- A writable `computed({ get, set })` can be bound; its getter stays
  authoritative and the DOM is corrected after React's handlers run.
- Server rendering writes the initial value; hydration attaches to the
  existing node.

The complete allow-list and caveats are in
[JSX signal children and host bindings](https://github.com/sakzw/react-fine-grained-signals/blob/main/docs/guides/jsx-bindings.md).
