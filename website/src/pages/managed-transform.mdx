# Managed Transform

`unplugin-react-fine-grained-signals` selects components and custom Hooks from
statically recognized reads or explicit opt-ins, then tracks synchronous reads
within the documented transform contract. For the default managed transform,
no `useSignalTracking()` calls are needed for reads the plugin can prove.

```ts [vite.config.ts]
import { defineConfig } from 'vite'
import signals from 'unplugin-react-fine-grained-signals/vite'

export default defineConfig({
  plugins: [signals({ mode: 'auto' })],
})
```

The package also provides `/rollup`, `/webpack`, `/rspack`, and `/esbuild`
entry points. With React Compiler, list `signals()` before the plugin that runs
the compiler.

```tsx
const temperature = signal(21)

function describe() {
  return temperature.value >= 25 ? 'warm' : 'mild'
}

export function Thermostat() {
  // No useSignalTracking(): the build adds a capture Hook and wraps each read.
  return (
    <p>
      {temperature.value}° — it feels {describe()}
    </p>
  )
}
```

## How it works

In the default `transform: "managed"`, a selected function gets one top-level
`useSignalCapture()` Hook, and statically proven synchronous reads are wrapped
in short capture scopes. This includes supported `.value` reads, inline
callbacks such as `items.filter((item) => item.done.value)`, and synchronous
call sites that may enter code the module cannot see. The plugin does not
inspect imported helper bodies to select their callers: a caller whose only
read is hidden inside an imported helper is not selected by `mode: "auto"`.
An imported helper call can be captured at its call site only when the caller
already has a managed boundary. Your own Hooks stay at the top level, in their
original order.

## Options

- **`mode`** — which functions opt in. `"auto"` (default) selects functions
  with statically recognized `.value` reads; `"manual"` requires a
  `useSignalTracking()` call or a `@signalTracking` comment; `"all"` selects
  every eligible JSX component.
- **`transform`** — `"managed"` (default) for per-read capture, or `"inject"`
  to insert a bare `useSignalTracking()` call instead.
- **`include` / `exclude`** — functions that filter module IDs.
- **`reactCompiler`** — how the plugin cooperates with React Compiler
  (default `"auto"`).

A `@noSignalTracking` comment opts a single function out.

## React Server Components

The transform cannot tell a Server Component from a Client Component by
itself. A module with `"use server"` is left alone; for everything else, keep
Server Components out with `exclude`/`include`, a `@noSignalTracking`
comment, or `mode: "manual"`.

This site is an example: Vocs renders pages as Server Components, so its Vite
config restricts the transform to the client-only demo components:

```ts [vite.config.ts]
signals({
  mode: 'auto',
  include: (id) => /\/src\/components\/.*\.tsx$/.test(id),
})
```

## What it does not track

The contract is deliberately narrower than a whole-function boundary:

- Reads after the first `await`, in `.then()` callbacks, timers, and event
  handlers run after render, so they are never render dependencies.
- JSX render props and `children` callbacks have no invocation guarantee; the
  plugin warns where it can see them.
- Props and React state are trusted to be plain data. An object passed as a
  prop that defines its own `map` reading signals is not tracked.
- User code a builtin runs implicitly on an untracked value — a `toString` in a
  template literal, a getter, an iterator — is not followed.

`useSignalTracking()` is a best-effort ambient boundary, both when written by
hand and when inserted by `transform: "inject"`; it is not an exact lexical
scope. For explicit lexical ownership of synchronous reads, use
`useManagedSignals()` from `react-fine-grained-signals/internal` inside
`try` / `finally`. A directly imported first-statement `useSignalTracking()`
call is preserved by the plugin when ambient collection is needed.

The full contract, including every supported pattern and diagnostic, is the
[plugin README](https://github.com/sakzw/react-fine-grained-signals/blob/main/packages/unplugin-react-fine-grained-signals/README.md#managed-tracking-contract)
and [Rendering optimization](https://github.com/sakzw/react-fine-grained-signals/blob/main/docs/guides/rendering-optimization.md).

## Diagnostics

The plugin emits structured warnings with a stable `diagnosticId`, source
location, and code frame. Select IDs that should fail your build with
`diagnostics.errorOn`; other diagnostics remain warnings, and the transform
output is unchanged. An unknown ID is a plugin configuration error.

| ID | What it reports |
| --- | --- |
| `RFGS001` | A Hook appears inside a signal-read expression or a call whose only reads occur there. |
| `RFGS002` | A call runs a Hook-calling function while its caller reads signals. |
| `RFGS003` | A JSX render-prop or `children` callback reads a signal, but ownership cannot be proven. |
| `RFGS004` | A `.value` read remains in a function parameter initializer. |
| `RFGS005` | `useSignalTracking()` is resolved only through a barrel/re-export. |
| `RFGS006` | `@signalTracking` has no component or Hook identity to attach to. |
| `RFGS007` | An anonymous default export has no identity derivable from the module name. |
| `RFGS008` | A component is both called as a plain function and rendered as JSX. |
| `RFGS009` | A component in a top-level `"use server"` module is left untransformed. |

```ts
signals({ diagnostics: { errorOn: ['RFGS001', 'RFGS003'] } })
```

The full explanations are in the [diagnostics reference](https://github.com/sakzw/react-fine-grained-signals/blob/main/packages/unplugin-react-fine-grained-signals/README.md#diagnostics).

## React Compiler and Fast Refresh

With React Compiler enabled, register `signals()` before the compiler plugin
so the signal reads are recognized first. The default `reactCompiler: 'auto'`
adds `"use no memo"` to transformed functions to prevent compiler memoization
from caching JSX that must respond to a signal. Use `reactCompiler: 'off'` only
when the compiler is absent or the affected components have been audited.
Prefer Managed Transform to `transform: 'inject'` with Compiler; injection is
a best-effort ambient boundary and compiler memoization can make it stale.

Fast Refresh has been exercised with the Vite 8/Oxc path for JSX edits and
Hook addition, removal, and reordering. Keep authored Hooks at top level and
in stable order, as required by React. See the plugin's
[Compiler guidance](https://github.com/sakzw/react-fine-grained-signals/blob/main/packages/unplugin-react-fine-grained-signals/README.md#with-react-compiler)
and [Fast Refresh qualification](https://github.com/sakzw/react-fine-grained-signals/blob/main/packages/unplugin-react-fine-grained-signals/README.md#fast-refresh).
