# v0.2.1 release notes

Paired release of `react-fine-grained-signals` and `unplugin-react-fine-grained-signals`, both at version `0.2.1`.

This is a stabilization release with no intended breaking API changes. Upgrade the runtime and transform package together.

## Runtime and JSX

- A direct signal binding for `title` or `id` now removes its DOM attribute when the value becomes `null` or `undefined`, matching React DOM. TypeScript accepts nullish signal values for these two props, and the shared host-tag path also works in the SVG namespace.

## Transform plugin

- Non-fatal transform diagnostics use the bundler warning API when the host exposes one. Warnings retain their code frame and source location; direct transformer calls keep a `console.warn` fallback.
- In `mode: "auto"`, an anonymous default JSX component with no statically visible signal read no longer warns just because it is anonymous. `mode: "all"` continues to report one it cannot transform, and `mode: "manual"` remains quiet.

## Packaging

- The exact Node 24.21.0 developer runtime pin warns on a mismatch instead of attempting an automatic runtime download, so package operations can proceed under a nearby installed Node version. The runtime package's supported Node range remains `>=22.0.0`.

## Known limitation

- **Pre-existing managed-mode Fast Refresh limitation (not a v0.2.1 regression).** The managed transform places the component body, including authored Hook calls, inside a generated `try/finally` so tracking cleanup runs on return, throw, and Suspense. React's [Rules of Hooks](https://react.dev/reference/rules/rules-of-hooks) prohibit calling Hooks inside `try`, `catch`, or `finally`; this generated structure is outside that documented rule. In the audited Vite 8 / Oxc setup, the Refresh transform emits `$RefreshSig$` and registers the component but omits its Hook signature for this structure. Adding, removing, or reordering Hooks can therefore retain the previous component state and fail with a Hook-order error until reload. A plain React control with Hooks in `try/finally` reproduces the Oxc signature behavior, but that control also violates the Hook rule; the issue is the interaction of Oxc's analysis with a managed structure that RFSG itself generates. This structure predates v0.2.1 and was not changed in this release.
- `transform: "inject"` avoids that generated boundary and passed the audited Hook-edit fixture. It inserts a bare `useSignalTracking()` Hook and provides the same best-effort boundary as a hand-written Hook; it does not provide managed mode's exact synchronous `try/finally` tracking contract. It is an available alternative, not a contract-equivalent replacement. No automatic workaround or managed-transform redesign is included in v0.2.1.
