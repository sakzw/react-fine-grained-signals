# v0.2.1 release notes (draft)

> Draft for the paired `react-fine-grained-signals` and `unplugin-react-fine-grained-signals` 0.2.1 release. No package has been published, tagged, or released.

This is a stabilization release with no intended breaking API changes. Upgrade the runtime and transform package together.

## Runtime and JSX

- A direct signal binding for `title` or `id` now removes its DOM attribute when the value becomes `null` or `undefined`, matching React DOM. TypeScript accepts nullish signal values for these two props, and the shared host-tag path also works in the SVG namespace.

## Transform plugin

- Non-fatal transform diagnostics use the bundler warning API when the host exposes one. Warnings retain their code frame and source location; direct transformer calls keep a `console.warn` fallback.
- In `mode: "auto"`, an anonymous default JSX component with no statically visible signal read no longer warns just because it is anonymous. `mode: "all"` continues to report one it cannot transform, and `mode: "manual"` remains quiet.

## Packaging

- The exact Node 24.20.0 developer runtime pin remains in place. A mismatch now warns instead of attempting an automatic runtime download, so `npm pack` can proceed under a nearby installed Node version. The package's supported runtime range remains `>=22.0.0`.

## Known limitation

- Managed transform mode still has a Fast Refresh limitation under the audited Vite/Oxc setup: changing a transformed component's hooks can preserve stale state and fail with a “Rendered more/fewer hooks” error until a full reload. The managed boundary places component hooks inside `try/finally`, where the audited refresh transform does not include them in its hook signature. `transform: "inject"` did not show this limitation in that fixture. The managed lifecycle was left unchanged because no low-risk, cross-bundler fix was established for this release.
