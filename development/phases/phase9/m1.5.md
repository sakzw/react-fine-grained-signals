# Phase 9 M1.5 — Alien-derived runtime rebase

## Decision

The Alien-derived architecture is a viable research candidate, but it is **not selected for production**. The integrated prototype passes 82/82 candidate checks after a commit-phase computed-promotion design fixed the nested React/DeepSignal boundary contract. No production runtime or package metadata changed, and M2 has not begun. The lack of a complete M1.5 authoritative performance matrix still prevents migration.

The earlier Stage 2 stop was caused by an accessor/helper-object prototype, not by Alien's architecture. Its `source/read@1` and `source/write-read@1` screens were 3.25x and 5.36x slower than v0.1.1. Investigation found that this prototype added accessor-to-helper dispatch and a node-kind check. Replacing it with an inline class getter brought the bare candidate close to the Alien high-level shape; subsequent RFSG layers were then investigated rather than treating the first screen as a task boundary.

## Balanced diagnostic and packaging

The integrated runtime/interop screen uses six fresh-process rounds for three runtimes in all six permutations (`ABC`, `BCA`, `CAB`, `ACB`, `CBA`, `BAC`), so each runtime occupies each absolute position twice and every pair runs in each order three times. Two-runtime comparisons alternate forward and reverse order. Each process uses the frozen M1b count, three warmups, and seven samples. Raw data and per-round order are in [`interop-overhead-results-balanced.json`](../../../benchmarks/phase9/m15/interop-overhead-results-balanced.json).

For the integrated render-enabled candidate versus the `Object.is` baseline, median paired duration ratios were 1.08x for source/read and 1.93x for effect observed-write; the candidate's helper-call alternative measured 1.91x and 2.26x. Foreign effect observed-write versus the local helper path was 2.53x. The final four-pair ReactDOM/JSDOM diagnostic measured `useSignalValue` at 1.13x (rounds 1.23, 0.87, 1.03, 1.29; range 0.87–1.29) and the deep selector at 0.98x (1.07, 0.98, 0.91, 0.97; range 0.91–1.07) versus the candidate control adapter. These are noisy, selected diagnostics, not an authoritative M1b or full M1.5 matrix. No calibration or M1b matrix was run; no release performance interpretation is made.

The final candidate's minified ESM bundle is 45,595 bytes (11,302 bytes gzip); the control is 28,215 bytes (7,542 bytes gzip). Both keep `react` external and bundle `alien-signals/system`. This supports evaluating `alien-signals` as a build-time dependency if the published package ships only bundled outputs; keep it a runtime dependency if any published entry leaves that import external. React remains a peer dependency. No dependency topology change was made.

## Correctness, limits, and next decision

The complete candidate suite is 82/82: 18 React adapter checks, 35 deep core checks, two focused DeepSignal/React checks, and 27 copied React DeepSignal checks. The nested-computed boundary contract now passes. The React diagnostics are limited to four paired rounds, and the full frozen M1.5 performance matrix remains incomplete; the candidate therefore remains an unselected benchmark-only prototype. No production source, public exports, or package metadata changed; M2 remains unstarted.
