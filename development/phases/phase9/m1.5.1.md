# Phase 9 M1.5.1 — Adapter architecture rebase

## Outcome

M1.5.1 produced a compositional, benchmark-only Alien-derived candidate. Its graph, queue, dependency cleanup, and computed lifecycle have one implementation; render/speculation, foreign-readable bridging, React hooks, and DeepSignal adapt around it. Do not migrate production from this result alone: the full matrix is descriptive, and the candidate has not been shaped into a production package. M2 has not started.

The verified starting `HEAD` and `origin/main` were `987b05c5cc278286ba1d236883587794a2864208`. The M1.5 report now correctly identifies public starting main as `9c979b2b2b0a951c30e1bc98675fa8ff1d7d7f44`; `0762e5098d2ce88d9b1c8546f8238d35ffb70f63` was an intermediate development commit.

## Compatibility contract

The local `v0.1.1` tag tree has no `src/core/interop.ts`; its tree therefore does not establish mixed v0.1.1/new-runtime graph interoperability as a published contract. Phase 4 documentation and duplicate-copy tests establish same-version duplicate-package interoperability. M1.5.1 consequently tests independent copies of the candidate protocol without carrying forward compatibility with arbitrary intermediate development contexts.

The candidate uses one V2 global lexical execution owner (`graph`, `render`, `untracked`, or `undefined`) and retains the V1 per-readable protocol for readable identity and subscriptions. The two roles are separate: owner scopes decide who receives the read; a readable's V1 protocol connects that read to another runtime's graph. No graph, scheduler, or batch state is shared. Cross-copy batches are still not atomic.

## Architecture and ownership

- `alien-derived-runtime-owner-core.mjs` is the sole graph implementation. Same-copy reads still settle/link through Alien's local `activeSub`; effects install/restore one shared graph owner at the outer callback boundary. When that runtime already owns the scope, nested graph work avoids another shared owner write.
- `alien-derived-runtime-render-adapter.mjs` owns attempt-local snapshots, speculative computed state, revision checks, and commit-time promotion. Render attempts supply owner-local speculative state instead of a separate global speculative-depth counter.
- `alien-derived-runtime-foreign-adapter.mjs` holds the V1 readable bridge and local external nodes. It does not duplicate graph algorithms.
- `alien-derived-runtime-react-adapter.mjs` supplies `useSignalValue`, bare tracking, and managed tracking. `alien-derived-deep-signal-owner-engine.ts` reuses `createDeepSignalFactory`; the production engine only gained optional internal speculative hooks, whose defaults retain the current production path.
- V2 ownership is lexical and restored in `finally`: graph inside render switches ownership to graph; untracked suppresses a nested graph read; render inside graph and nested render attempts take the innermost owner; nested graph scopes select the innermost subscriber.

The owner-core duplicate-copy smoke passed for foreign signal/computed reads, foreign untracked reads, dynamic dependency switching/release, disposal, and cross-copy batching. React candidate checks also cover a foreign render read, nested graph inside render, inner render inside graph, speculative computed promotion, and suspended-attempt abandonment. The focused Vitest suite passed 150/150 tests across seven files. `owner-core-check.mjs` returned `{"status":"pass","batchEffectRuns":2}`.

## Package shape and recommendation

The bundled M1.5.1 candidate is 44,231 raw bytes / 11,404 gzip bytes; the control is 45,599 / 11,374. Both bundle `alien-signals/system` (no external import) and leave React external. This is evidence that Alien need not remain a shipped runtime dependency under this bundling shape; it does not decide package topology. React remains a peer-shaped external.

The compositional owner architecture is the selected research direction over M1.5's multiple independently mutated collectors/depth state. It should proceed to a production-shaped candidate review, not directly replace production: the benchmark bundle is not a production package, source/read remains 1.42x v0.1.1 in this matrix, DeepSignal allocation is higher than current, and bundle/license/package policy still need review. Production runtime semantics were not changed, and no M2 work began.
