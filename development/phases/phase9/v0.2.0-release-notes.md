# v0.2.0 release notes (draft)

> Draft for the GitHub Release of `v0.2.0`. Nothing has been tagged, published, or released. Links point at the `v0.2.0` tag so they keep working after later docs changes.

`react-fine-grained-signals` 0.2.0 and `unplugin-react-fine-grained-signals` 0.2.0 are released together. Upgrade both in the same change; the [migration guide](https://github.com/sakzw/react-fine-grained-signals/blob/v0.2.0/docs/migration/v0.2.md) ([日本語](https://github.com/sakzw/react-fine-grained-signals/blob/v0.2.0/docs/migration/v0.2.ja.md)) covers every step below.

## Breaking changes

- **Render tracking hooks renamed.** The root `useSignals()` is now `useSignalTracking()` (best-effort tracking). The `/runtime` `useSignals()` is now `useManagedSignals()` (exact tracking), and its scope's `f()` is gone: call `finish()`.
- **Plugin and runtime must be upgraded together.** The v0.1.1 plugin emits code against the removed APIs, and its peer range (`^0.1.1`) excludes 0.2.0. A custom `importSource` wrapper must re-export the root `useSignalTracking` and the `/runtime` `useManagedSignals`.
- **Plugin annotations renamed.** `@useSignals` is now `@signalTracking`, and `@noUseSignals` is now `@noSignalTracking`. The old names are ignored without a warning.
- **`alien-signals` is a regular dependency**, pinned to `3.2.1`, instead of a peer dependency.
- **v0.1.x and v0.2 signals do not interoperate.** v0.2 uses a new identity brand. Upgrade every package that bundles or depends on RFSG together. Several copies of v0.2 on one page do interoperate.
- **`deepSignal` is rejected in root-only positions.** TypeScript no longer accepts it in `useSignalValue()`, as a signal child, or as a bound host prop. Use `useDeepSignalValue()` instead, or read the deep state in a tracked component.
- **Plugin targeting changed.**
  - Class fields (`class Page { Header = () => … }`) are no longer transformed.
  - Object-literal method components (`{ Home() { … } }`) are now transformed.
  - Some functions no longer get a boundary of their own; their reads count toward the calling component instead:
    - a PascalCase function called as a plain function (`Title()`);
    - an `Array.from(…, Star)` callback;
    - a keyed callback destructured before use (`const { Row } = parts; items.map(Row)`).
  - The Vite plugin's `transform` hook is now `{ order: "pre", handler }`, so it runs before `@vitejs/plugin-react`'s compiler wherever it sits in `plugins`.

## Runtime

- The graph core is rebuilt on `alien-signals/system` 3.2.1.
- Effects:
  - Nested effects keep v0.1.1's ownership: a child is disposed when its parent re-runs or is disposed.
  - `untracked()` now also suppresses tracking by another installed copy of RFSG.
- `deepSignal`:
  - Array mutation methods no longer subscribe the caller.
  - `Object.keys`, `for...in`, `Object.hasOwn`, and `hasOwnProperty.call` track key additions and removals only.
  - Keys inherited from `Object.prototype` are reactive in dictionary-style objects.
  - `includes`, `indexOf`, and `lastIndexOf` find a stored raw object. In v0.1.1 they missed it, so `items.splice(items.indexOf(a), 1)` removed the wrong element.

## JSX and direct bindings

- A host prop can switch between a signal and a plain value without remounting the element or its children. Bindings attach through a ref on the element, and your own `ref` is still called with the element.
- Bound `value`/`checked` keep the element's reset default in step with each signal write. `form.reset()` and React 19's reset after a `<form action>` restore the value last written to the signal (see the known limitations for user edits).
- The package root exports `createElement`. It is the classic factory that compilers fall back to for `<div {...props} key="k" />` under `jsxImportSource`, and is not meant to be called directly.
- A signal inside an array child is keyed by its position.
- A bare `useSignalTracking()` window closes when React starts committing.
- `JSX.IntrinsicElements` is now an interface, so it can be augmented.

## Transform plugin

- Signal reads in parameter defaults are moved behind the boundary, so they are tracked. In TypeScript, the generated parameter keeps the original's optionality.
- Per-item render callbacks stay off a boundary:
  - callbacks passed to `map`, `flatMap`, and `forEach`;
  - `Array.from`'s `mapFn`;
  - a keyed slot destructured one step before use.
- File extensions match case-insensitively (`.TSX`, `.JSX`).
- Every entry has a `default` export condition, so a CommonJS config can load the plugin through `require(esm)`.

## Known limitations

These were reviewed for v0.2.0 and deliberately left for later releases.

- **Fast Refresh (present since v0.1.1).** In a component the plugin transformed, adding, removing, or reordering a hook during Fast Refresh can fail with "Rendered more hooks than during the previous render". A full reload recovers.
- **Form reset after a user edit.** After the user edits a bound field, React resets the field's default to the last rendered value, so a reset restores that value rather than the signal's. To decide what a reset shows, write the signal in the action or in `onReset`.
- **Bound `value`/`checked` and rejected input.** They do not snap back when `onChange` rejects the input.
- **`deepSignal` writes subscribe the writer (present since v0.1.1).** An effect that assigns into `deepSignal` state subscribes to the keys it writes.
- **`deepSignal` collections.** `Map` and `Set` are not redesigned yet.
- **`null` title and id.** A bound `title` or `id` written to `null` leaves an empty attribute instead of removing it.
- **`auto` mode detection.**
  - React Server Components are not detected. Use `exclude`, `@noSignalTracking`, or `mode: "manual"`.
  - Destructured reads (`const { value } = count`) are not detected.
  - A keyed callback's reads are not credited to its caller.
- **Module formats and Node versions.**
  - The runtime ships ESM only.
  - The plugin requires Node `^22.18.0 || >=24.11.0` (Babel 8).
