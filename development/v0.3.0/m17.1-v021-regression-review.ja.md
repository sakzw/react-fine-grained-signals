# M17.1 — v0.2.1比較レビューと回帰修正

開始基準: `main` / `03af31d71f9c9bb95de091c1c32b1323587c7524`(M17記録時点)
比較基準: tag `v0.2.1` / commit `58f01b9314a1b09b88b162c57912ff736201e790`
終了SHA: `2d57af1`

## 結論

M17は「再現性のあるrelease blockerなし」と判断したが、v0.2.1との差分を対象にした独立レビューで、v0.2.1では動いていた利用コードが壊れるか大幅に遅くなる回帰を3件、新機能の不具合を4件確認した。いずれも再現テストを追加して修正し、修正前のコードでテストが失敗することを確認した。**M17の「release blockerなし」はM17.1の修正後に成立する判断として読み替える。** 公開APIの追加・削除はない。

レビューはcore/deepSignal、JSX runtime/React hooks、transformの3領域に分けて行い、各指摘をv0.2.1 worktreeとの比較実行またはテストで確認した。

> 追記: 下表の`for...of`の全件コピーはJavaScriptの意味論を変えたため、[M17.2](m17.2-semantic-regression-closure.ja.md)でiterator stepごとのcaptureへ置き換えた。「未対応として残すもの」のうち部分mount、transform負荷、Hook、migration guideの項目もM17.2で対応した。

## P0: v0.2.1からの回帰(修正済み)

| 回帰 | 原因 | 修正 | 計測・確認 |
|---|---|---|---|
| managed transformがcallback内などのreadを追跡せず、警告なしでstale render | per-read captureが`.value` member chainだけをwrapし、`map`/`flatMap`/`forEach`以外のinline callback(`filter`、`reduce`、`find`、IIFE)、callee内で後から行われるdeep read(`JSON.stringify(deep.value.x)`、局所helper)、`in`、spread、`for...of`のiterationがcapture外になった。v0.2.1の関数全体boundaryでは追跡されていた | tracked値を読むinline callbackを持つcall/new、tracked値を引数に取るcall、右辺がtrackedな`in`、tracked値のobject/array spreadを式全体でcaptureする。`for...of`はarray/Map/Set sourceを1つのcapture内でcopyし、loop変数をtracked aliasにする。他のiterableは遅延評価のまま。Hook呼び出しを含む式は従来のread単位captureに戻す | `react-execution.test.ts`に実行テスト4件。filter/reduce/IIFE/nested callback、JSON.stringify/`in`/spread/helper/for-of(要素変更とpush)の再描画、Hook非wrap、generatorの評価順序を確認 |
| deepSignal経由のDate・class instance readが約28倍遅い | `wrap()`がopaque値ごとに`isStandardCollection`を呼び、collection判定のためthrowするinternal-slot probeを4回実行していた | prototypeが標準collectionのものと一致する場合だけbrand probeを行う | 20k回のDate+class read: 22.2秒 → 0.35秒(同一マシン・同一script) |
| Map/Setのlookupがkeyの到達graph全体を走査し、未登録keyでthrowする | `get`/`has`/`delete`が書き込みと同じ正規化(graph検証)を行っていた | lookupは格納済みkeyのidentity(proxyのraw、正規化済みcarrier)だけを解決する。凍結object、accessor付きobject、prototype等の未登録keyは`false`/`undefined`を返す(v0.2.1と同じ) | 20k node graph上のkeyで200回lookup: 58.7秒 → 7ms。`deep-signal-collections.test.ts`に回帰テスト |

## P1: 新機能の不具合(修正済み)

| 不具合 | 修正 |
|---|---|
| radio/checkbox groupで`onClick`が`preventDefault()`すると、signalは試行値のままbrowserがDOMを戻し、不一致が残る | click後のtaskで`defaultPrevented`を確認し、その間にhandlerが別の値を書いていなければsignalを元の値へ戻してgroup全体を再同期する |
| `bindChecked`がnative `change`で更新していたため、Reactがclickから合成する`onChange`内では古いsignal値が見えた(migration guideの記述と矛盾) | group bindingと同じくtargetのnative `click`で更新する。writable computedが拒否した値のDOM復元はdispatch後の次taskで行う。`preventDefault()`時の復元も同様 |
| 読むだけで書かないprimitive collection keyのversionが永久に残る(検索・cache・存在確認で無制限に増え、以後のmutationごとに再sweepされる) | collection sweepはwatched flagではなく実際のgraph subscriberで判定する。破棄するversionはrevisionを1つ進め、render中にそのkeyを読んで未commitのattemptはcommit時に変化を検出して再renderし、新しいversionを読む |
| proxy経由のMap/Set iteratorが`Iterator.prototype`を継承せず、`keys().toArray()`等のIterator helpersが使えない(v0.2.1では使えた) | `%IteratorPrototype%`を継承させる |

`bindChecked`の変更により、writable computedが拒否したcheckbox値のDOM復元はclick直後ではなく次taskになる。既存テスト1件をこの契約に合わせて更新した。`preventDefault()`と同時に、ユーザーがclickした値と同じ値をhandlerが同期的に書いた場合は、bindingの書き込みと区別できないため元の値へ戻る。確認後に後から書く通常のpatternは保持される。

英日のmigration guide、`jsx-bindings`ガイド、pluginの英日READMEに、capture範囲とclick時の更新・cancel動作を反映した。

## 未対応として残すもの

| 項目 | 分類 | 内容 |
|---|---:|---|
| `#sync`途中で例外が出た場合の部分mount binding | 2 | radio source競合などで途中のmountが例外を投げると、それまでにmountしたsubscriptionが解放されない。errorパスのみ |
| select/radioへの非string外部書き込み | 2 | subscription内で例外がlogされ、DOMが古い選択のまま残る。型では禁止済み |
| 同一helperを多数の呼び出し位置から使う場合のtransform時間 | 2 | 呼び出し位置ごとにhelperを再解析する。200 read helperを400回呼ぶfixtureでv0.2.1の1.8秒に対し26.8秒(レビュー時の計測、負荷のあるマシン) |
| import helperの引数にHook呼び出しがある場合のcapture | 2 | `format(useContext(Ctx), s.value)`がcapture closure内に入る。実行時は無条件に呼ばれるため動作するが、Rules of Hooksのlint形に反する |
| managedで追跡できないpattern | 3 | custom hookの戻り値のproperty read、array destructuring、default付きdestructuring。後2者は既存の警告対象 |
| migration guideに未記載のbreaking change | 2 | `<option>`/`<li>`/`<meter>`/`<progress>`の`value={signal}`がthrowする(v0.2.1ガイドでは片方向attribute bindingとして記載)。`number`/`range`/`date`/`color`/`hidden`のinputは`bindValue`非対応。Map/Set subclass、異realm collection、凍結Mapをstateに入れるとthrow。`map.get(k)`がproxyを返すためidentityが変わる |
| bundle size増加 | 4 | v0.2.1の予算値比で`index-full`(17.28 → 21.76 kB gzip)、`deep`(12.22 → 14.13 kB)など2割強増。v0.3の機能追加分で、全予算内 |

分類はM17と同じ(1 v0.3.0で改善価値が高い、2 後続へ送れる、3 意図した設計制約、4 対応不要)。migration guideの未記載事項は公開前に追記する価値がある。
