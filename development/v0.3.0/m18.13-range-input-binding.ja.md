# M18.13 — Range Input Binding & Migration Documentation

## 概要

既存の`bindValue`で`input[type="range"]`を使えるようにした。DOMの文字列値を`FormBindableSignal<string>`で同期し、数値変換やmin/max/stepの独自補正は行わない。M18.8で対応済みの`number`入力を移行ガイドへ反映し、古いruntime error文を現在の文言へ更新した。

## 実装

- runtimeのstring input allow-listへ`range`を追加。既存のinput binding listener、React event dispatch順、Signal購読、cleanup、form reset処理を再利用した。
- 公開JSX型で`type="range"`を許可し、`FormBindableSignal<string>`は受け入れ、numeric Signalは拒否する型テストを追加した。
- binding runtimeが独自に`valueAsNumber`を読んだりmin/max/stepを補正したりしない。`.value`の設定・ユーザー操作で生じるrange controlのsanitizationはnative browser behaviorに委ねる。
- English/JapaneseのJSX binding guide、移行ガイド、WebsiteのDirect Binding guideを更新した。移行ガイドにはnumber/range対応を後から追加した経緯を残し、v0.2.1の歴史的な`value={signal}`記述は消していない。
- Form Binding Demoにrange sliderを追加。repository modeのtarball lock integrityも更新した。website smoke runnerは`SMOKE_BROWSER=chromium|firefox|webkit`で同じ検証を実行できる。

## 採否と残課題

rangeのruntime挙動は既存string binding pathで成立し、新しい状態管理や依存は不要だったため採用した。ブラウザーがrange valueを補正する範囲はnative semanticsに依存するので、アプリケーションはsignal値の数値化を必要に応じて明示する。通常のCIはpush後に確認する。npm publish、version、tag、GitHub Release、Pages deployは実施しない。
