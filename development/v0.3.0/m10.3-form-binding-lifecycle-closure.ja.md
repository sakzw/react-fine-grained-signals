# M10.3 Form Binding Lifecycle Closure

## 基準と再現

- 開始基準: `main` / `fcd6cf6432f3c3a3c2ed00cec17865a95809f6c9`
- 対象: Writable computed `bindValue` の遅延DOM補正timerと同一node上のbinding差し替え
- package versionは`0.3.0`のまま

入力拒否後の補正timerを残したまま、React `onChange`でbinding元をSignal AからSignal Bへ切り替える回帰を追加した。Signal Bの値を入力直後のDOM値と一致させることで、timerが「DOM値が今回の入力値のまま」という条件を満たし、disposed bindingのgetterで上書きする状況を再現した。修正前のfocused testは、DOMがSignal Bの`123x`ではなくSignal Aの`123`へ戻ることで失敗した。

## 修正

各`bindTextValue` closureが自身のtimer handleとactive状態を所有する。新しいinput eventではbinding世代を進めて古いtimerをcancelし、bindingの`dispose()`でもactive状態を落として世代を進め、timerをcancelする。NodeBinderが同じDOM nodeに再利用されて`attached`がtrueのままでも、古いbinding closureはDOMを書けない。

入力setter後にgetterを読み、値が入力値と一致していれば補正timerを予約しない。Signalの通常受理とcomputedの完全受理でtask予約を省き、拒否または異なる値へ正規化した場合はReactの委譲handlerより後のtaskで補正する。IME中にtimerが実行された場合は従来どおりDOMを書かず、最新getter値をpendingにして`compositionend`で反映する。

`tests/react-dom-binding.test.tsx`で誤っていた数字判定`/^\\d+$/`を`/^\d+$/`へ修正し、textarea bindingで数字の受理と非数字の拒否の両方を検証する。
