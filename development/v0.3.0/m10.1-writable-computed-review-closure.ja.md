# M10.1 Writable Computed Review Closure

## 基準と判断

- 開始基準: `main` / `ba3a18e4c6648b628c9f4d8a0d0733554edf4320`
- 対象: `computed({ get, set })`を`bindValue` / `bindChecked`に渡したときのDOM同期と`FormBindableSignal<T>`の型契約
- package versionは`0.3.0`のまま

Writable computedのsetterが入力を拒否すると依存signalが変わらず、通知も発生しない。その場合、DOMだけに入力値が残りgetterと食い違う不具合を再現テストにした。DOM再同期処理を一時的に無効にして実行すると、`input.value`が`123x`のままであることを確認した。実装後は同じテストが通る。

getterを正本とし、書き込み後に`peek()`で現在値を確認する。getter値が入力値と異なる場合だけ既存のDOM適用関数へ戻す。単一値は`Object.is`、multiple selectは値とoption順を含む浅い配列比較を使う。通常のSignalや完全に受理された値では追加のDOM書き込みを行わない。textのIME composition中は補正値をpendingにし、`compositionend`後に適用する。既存のDOM setterが同一値を省き、caret範囲を維持する。checkboxとsingle/multiple selectにも同じgetter基準の再同期を適用した。

Writable computedのsetterは既存どおり`batch()`内で実行されることを確認した。二つの依存signalを更新するsetterをbindingから呼び、effectが更新前・更新後の値だけを観測するテストを追加した。

## 型とドキュメント

`FormBindableSignal<T>`を維持し、型専用brandを公開文字列プロパティから非公開`unique symbol`へ変更した。実行時プロパティは増えない。`signal()`、`useSignal()`、書き込み可能な`computed()`が返す型をそのまま保持し、汎用フォームコンポーネントのpropも`FormBindableSignal<T>`とする。`Signal<T>`へ広げるとJSX binding capabilityが失われる。getter-only computedは引き続き型で拒否する。

英語・日本語のJSX bindingガイドとmigration guideに、型の保持方法、汎用field例、brandが実行時プロパティではないこと、setterの拒否・正規化時はgetterへDOMを戻す契約を追記した。hooks / core primitivesガイドも型名と戻り値を一致させた。

## 残る制限

独自のwritable computed setterが非同期で後から依存signalを更新する場合、bindingの直後に行うgetter確認では将来の結果を予測しない。非同期完了時にsignalが更新されれば通常のsubscription経路でDOMへ反映される。同期setterについては拒否・正規化ともにgetterとDOMが同期する。
