# M18.7 — Deep Selector Hook DX

開始HEAD: `6db77893cda07ba96a2eb3faa0876e05d01c4cf3`

## 1. 既存APIの問題

`useDeepSignalValue`は、signal stateだけを読むselectorでも必須の空依存配列 `[]` が必要だった。一般的なHookではdepsを省略できるため、signal-only selectorの記述が冗長で、`useComputed`のclosure規則とも揃っていなかった。

## 2. 変更した公開API

```ts
useDeepSignalValue<T extends object, S extends SignalSnapshot>(
  source: DeepSignal<T>,
  selector: (value: T) => S,
  dependencies?: DependencyList,
): S
```

Runtimeのselector storeや公開型のselector結果制約は変更せず、第三引数をoptionalにした。

## 3. dependencies省略の意味

- 省略時はselectorの初期closureを保持し、storeのmemoization keyはsource identityのみ。親React renderで新しい関数identityが渡ってもstoreを作り直さない。Signal以外の値をselector closureに含めてはならない。
- `[]`は明示的な空依存配列であり、明示deps modeを選ぶ。省略modeと同じくsignal-only selectorを使えるが、同じ呼び出し箇所で両modeを切り替えると、原因を示す`UseDeepSignalValueModeChangeError`を投げる。
- `[prefix]`などを渡した場合は従来どおり、sourceまたはdeps変更時に新しいstoreとselector closureを作る。selectorがpropsなど非Signal値を読む場合は全て列挙する。
- 明示配列の長さは初回renderから固定。変更時は従来のdependency-length errorを投げる。

Hookの数と呼び出し順は固定。省略modeのmemo depsは`[source]`、明示modeは`[source, ...dependencies]`となる。source identityが変わればどちらのmodeでも購読storeを更新する。

## 4. React / Concurrent正確性

selectorは既存どおりstore生成時に閉じ込める。commit済みstoreをrender中に書き換える仕組みは追加していないため、Suspenseで中断されるsource変更renderは候補storeだけを作り、既存storeのselectorを差し替えない。source切替後は古いsignalのsubscriptionを外し、新sourceのproperty-level trackingへ移る。

既存のError Boundary経由の例外伝播、primitive snapshot、`Object.is`、deep property購読、StrictMode cleanupの実装経路は維持した。SSR/hydrationテストは省略形式を使うよう更新。Suspense中断後にsourceを切り替えるfocusedテストを追加した。

## 5. TypeScriptと互換性

型fixtureで省略時のprimitive推論、`[]`、`[prefix]`、optional/array element結果、object snapshot拒否を確認。既存の必須deps呼び出しは引き続き有効。変更は第三引数を省略可能にする追加互換のAPI変更で、Runtime/Managed Transformや他Hookの仕様変更はない。

## 6. 性能とbundle

selector storeの生成規則は維持した。テスト上、mount時のselectorはstore作成とsubscription評価で2回、signal-only省略modeでは親render時のstore再生成・selector再評価は0回、選択値変更時は再評価1回。無関係property更新ではselector再評価も再renderも発生せず、unmount後は購読が残らない。

`pnpm size`は全budgetを通過。主な結果: `core+hooks` 9.68 kB gzip、`deep` 15.27 kB gzip、full entry 23.87 kB gzip、control-flow `utils` 9.39 kB gzip。比較用に基準HEADの同条件sizeを取り直していないため、サイズ差の定量的な主張はしない。機能分岐追加による影響は既存予算内。

## 8. 残課題

- 基準HEADと候補のpaired microbenchmarkは実施していない。ここでは公開APIの省略可能化であり、selector store機構やhot pathを変えていないため、追加最適化は行わなかった。
- Fast Refreshの専用再実行は未実施。この変更はHook state構成やmodule transformを変えず、既存Hookと同じmemo/ref規則を使う。
- npm公開、version変更、Git tag、GitHub Release、Pages deployは行わない。
