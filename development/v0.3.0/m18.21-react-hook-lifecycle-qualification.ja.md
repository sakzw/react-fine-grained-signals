## Fast Refresh Consumer

`m18.21-fast-refresh.mjs`が一時Viteアプリを作成し、実際のファイル編集でHMRを発生させてChromium上の状態を検証する。実行環境はVite 8.3.4、React 19.3.0。

- StrictMode下でReact component stateを変更してから、同じexport形状のソースを編集し、stateが保持されることを確認。
- 通常の`useComputed`とwritable `useComputed`について、HMR後に更新されたgetter/setterが使われることを確認。setter経由で元Signalを変更し、`useSignalValue`で派生値を読むConsumerとして検証した。
- `useSignalEffect`のHMR前cleanupと再接続を確認。再接続後のactive effectは1つだけで、Signal更新によるeffect実行も1回。
- unmount後はeffect cleanupが実行され、その後のSignal更新でrender/effectが増えないことを確認。再mount後の購読も確認。
- Browser console errorは0件。

最初の試行では、追跡HookもManaged Transformも使わず通常のReact renderから`.value`を読むConsumerを作り、表示が更新されない結果になった。これはテスト用ConsumerがRFSGの購読契約に従っていないためであり、製品不具合ではない。正しい`useSignalValue`経由に直した試行では上記の全assertionが通過した。HMRスクリプト最終JSONの`localStateAfterHmr`は意図的なunmount/remount後の値であり、HMR直後のstate保持はスクリプト内で別途assertしている。

## React lifecycle / 正確性

- `tests/react-signal-effect.test.tsx`にSuspense transitionケースを追加。依存値変更後のrenderがsuspendした間は直前にcommit済みのeffectが有効で、Signal更新がそのeffectを再実行する。pending renderを解決してcommitした時点で旧cleanupと新effect接続が発生する。
- dependency length違反でError Boundaryへ到達した後、旧effectのcleanup、boundaryを再生成した後の新effect接続、Signal更新、unmount cleanupを確認。
- 既存の`useComputed` testsはsuspended/abandoned render時にcommit済みgetter/setterを保つケースを含む。変更対象を含むfocused suiteとして`tests/react-signal-effect.test.tsx`、`tests/react-hooks.test.tsx`、`tests/ssr.test.tsx`を実行し、53 tests passed。
- React Compiler suite: 30 tests passed。
- StrictModeは既存のeffect cleanupテストを再利用。SSR/hydrationは既存SSR suiteを再実行。
- 契約違反テストで境界をresetする場合、失敗したReact subtreeを保持したままpropsだけ差し替えるのではなく、Error Boundaryをkeyで再生成する。これはError Boundaryの回復操作を明示するためのtest setup。

## 保持heapとrender数

既存の`m18.20-hook-cost.mjs`にrender回数とroot unmount後のGC測定を追加した。Node 24.21.0、React 19.3.0、500 rows、12 updates、2 warmups + 9 samples。baselineとcandidateは交互順で実行。

| 指標 | baseline中央値 (min–max) | candidate中央値 (min–max) | 差 |
|---|---:|---:|---:|
| mount | 43.58 ms (37.82–72.35) | 48.51 ms (38.92–67.38) | +4.93 ms、分布は重なる |
| update / commit | 10.74 ms (8.70–12.87) | 12.84 ms (10.61–22.72) | +2.09 ms、分布は重なる |
| root mounted retained heap | 4,941,576 B (4,866,552–4,996,696) | 5,023,424 B (4,983,352–5,100,560) | +81,848 B |
| root unmount後 | 2,271,920 B (2,206,480–2,325,664) | 2,279,320 B (2,254,400–2,355,376) | +7,400 B、分布は重なる |
| Row render / sample | 6,500 | 6,500 | 差なし |

M18.20での稼働中保持heap差+68,784 Bより今回の中央値差は大きいが、測定分布が重なり、unmount後の差は小さく分布内に収まる。保持量はHook refを含むReact treeの状態に比例する観測であり、effect callbackや購読がunmount後も同程度保持される証拠は得られなかった。effect setup/cleanup数も各sampleで期待値6,500に一致する。CPU差もばらつきが大きく、この測定から性能回帰とは断定しない。
