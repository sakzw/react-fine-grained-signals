# M18.6 — Reactive Match DX Improvement

## 問題

M18.5のControl Flowデモでは、`<Match when={view.value === "list"}>`の式を親が評価していた。そのためSignal更新のたびに親コンポーネントが再レンダーされ、分岐処理が`Switch`の追跡境界の外にあった。回避策として条件ごとの`computed` / `useComputed`を用意するのは冗長だった。

## API設計と実装

`Match`に`equals`を追加した。

```tsx
<Switch fallback={<p>Unknown view</p>}>
  <Match when={view} equals="list">List</Match>
  <Match when={view} equals="details">Details</Match>
</Switch>
```

- `when`はplain valueまたは`ReadonlySignal<T>`。
- `equals`がある場合、`Switch`内で読んだ`when`の値と`equals`を`Object.is`で比較する。truthy/falsyに関係なく値比較し、最初に一致した分岐だけを返す。predicate APIではない。
- `equals`を省略した場合は、従来どおり`when`のtruthy判定。`equals={undefined}`はown propertyの有無で区別し、`Object.is(value, undefined)`を実行する。
- `Match`にはHookを追加せず、Signal購読と動的依存の整理は既存の`Switch`管理境界を使う。`Match`単体はこれまでどおり`null`。
- 型は`when`から`equals`を制約し、equals branchのfunction childを`Extract<T, E>`へ絞る。truthy branchは`NonNullable<T>`の従来型を維持する。

Signalを直接渡すと`Switch`が購読する。`when={view.value === "list"}`のような式は親がJSX生成時に評価するため、親側がそのreadを追跡する。

## 正確性

`tests/control-flow.test.tsx`で以下を確認した。

- truthy互換と最初のMatch、fragment、fallback、Matchの並べ替え。
- `"list"`、`0`、`false`、`""`、`null`、`undefined`、`NaN`、`-0` / `+0`。特に`Object.is(-0, +0) === false`。
- Signal値変更、plain値変更、Signal/plain切り替え、nested Switch、分岐mount/unmount、親render差分、動的依存のcleanup、unmount後の購読cleanup。
- React 19 StrictModeのSignal更新、SuspenseでSwitchのfunction childが中断された後の依存回復とcleanup。
- equals branch childの型絞り込み、truthy childの`NonNullable<T>`、不正なequals値の型拒否（`tests/utils-types.tsx`）。

`tests/ssr.test.tsx`でSSR markupとhydrationのbranch一致、hydration warningなし、Signal更新時に親を再レンダーせず分岐更新することを確認した。既存の`useManagedSignals` abandoned-renderテストに加え、Switch child内でSuspendするケースも追加した。実ブラウザの開発サーバーFast Refreshは今回直接操作していない。実装は既存`Switch` boundaryを維持し、`Match`にHookや永続キャッシュを足していない。

## 性能比較

`benchmarks/m18.6-match-bench.mjs`を追加。Node 24.21 / Windows / React 19.3 / jsdomで、二分岐の小さなcomponent tree、3回warm-up後に各方式20回測定。時間はmount/update/unmountで`act()`をflushする前後差。範囲は各20回のmin〜max。

| 方式 | mount median (ms) | Signal update median (ms) | unmount median (ms) | 親render差 / update |
|---|---:|---:|---:|---:|
| 旧truthy条件（親で`signal.value === ...`を作る） | 2.100 (1.451–3.444) | 1.149 (0.984–1.734) | 0.535 (0.354–0.938) | +1 |
| `useComputed`で各条件を作る | 3.599 (2.123–27.510) | 1.254 (0.857–4.098) | 0.561 (0.443–4.690) | 0 |
| `Match equals` | 2.377 (1.569–6.744) | 0.905 (0.603–3.807) | 0.540 (0.307–15.099) | 0 |

初回renderとunmountは同程度。`equals`は`useComputed`方式に対してこのfixtureで測定可能な劣化を示さず、親renderを0にした。単一操作の小さなJSDOM測定にはGC・スケジューリングの外れ値があり、速度差の保証には使わない。実用上の主要効果は追加computedの記述をなくし、購読を`Switch`に局所化すること。

購読数は公開APIから整数として列挙できないため、テストで`coreRuntime.hasSubscribers`とunmount後のcleanupを確認した。構造上、親読み取り方式は親が元Signalを追跡し、`useComputed`方式は各computedが元Signalに依存して`Switch`が各computedを読む。新方式は2つのMatchから同じSignalを読んでも既存managed collectorでSwitchの依存として追跡する。新たなHookや別々のcomputed subscriptionは作らない。

## M18.6.1 — Match equals callback type narrowing fix

開始HEAD `47660f86c90768040b02f5fac1fa7a076c84a1f2`。M18.6で追加したequals overloadのcallback値型が`Extract<T, E>`だけに依存し、`T = string`、`E = "list"`のとき`never`になっていた問題を修正した。

- `MatchValue<T, E>`を追加し、`Extract<T, E>`が`never`になるprimitive supertypeの場合は`E`をそのまま使う。Unionとfalsy literalでは`Extract`による絞り込みを維持する。
- 公開`MatchProps<T, E>`は`E`省略時にtruthy branch、`E`指定時にequals branchだけを表すconditional typeにし、union callbackのcontextual typingで`implicit any`になる問題を避けた。`Match` overloadも同じ`MatchValue<T,E>`を使う。
- 型テストで`Signal<string>`/string literal、`Signal<number>`/number literal、literal Union、false/0/null/undefined、invalid equals、equals省略、直接`MatchProps`を確認した。Runtimeは変更していない。
- `exactOptionalPropertyTypes: false`の一時Consumer型fixtureでも確認した。JSX overloadの`equals={undefined}`は必須equals overloadでundefinedとして型付けされる。一方、型システム上`equals?: never`は省略時と明示undefinedを区別できず、exact optionalを無効にした環境では`MatchProps<T>`のlegacy branchへ`equals: undefined`を渡せる。optional property全般のTypeScript仕様による制約で、equals undefined自体を有効値として扱う公開契約を保ったまま、型ハックで拒否するのは妥当でないため許容する。
- JSXの数値属性`equals={0}`ではgeneric inferenceが`number`へ広げる場合がある。`MatchProps<number, 0>`など明示genericを指定した場合はcallbackをliteralに絞れる。`Signal<number>`+数値literalのJSX例は安全な`number`として型付けされる。

検証結果:

- `pnpm typecheck` — pass。
- `pnpm exec vitest run tests/control-flow.test.tsx tests/ssr.test.tsx --pool=threads --maxWorkers=1` — 2 files / 33 tests pass。
- `pnpm build` — runtimeとunplugin build pass。
- website repository-mode local pack、独立`pnpm install`、`pnpm typecheck`、`pnpm build` — pass。static site 33 files生成。
- `node tests/consumer-smoke.mjs` — packed consumer typecheck、Vite build、SSR/hydration、signal/form、cross-copy smoke pass。
- `exactOptionalPropertyTypes: false`を指定した一時TypeScript project — pass。一時fixture/configは削除済み。

この型修正はRuntime挙動、購読境界、StrictMode、SSR/Concurrent semanticsを変更しない。ロードマップはM18.6.1の完了に更新した。
