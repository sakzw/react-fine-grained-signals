# M18.14 — Native Range Interaction & Contract Hardening

## 状態

完了。Chromium、Firefox、WebKitの静的Website smokeがすべて成功し、既存React DOM binding testsも83/83 pass。

## 対象と変更

- `input[type="range"]`を実ブラウザーのマウス・キー操作で動かすsmokeを追加した。従来の`fill()`テストも維持している。
- native `input` / `change`の順序、React `onInput`がSignal更新後の値を読むこと、owner render数、signal外部更新、min/max/step変更、範囲外・刻み外Signal値、`range` / `text`のtype切替を確認する。
- smokeのブラウザー選択コメントをChromium/Firefox/WebKitに合わせた。ページ移動時にエンジンが中断したrequestを失敗と誤認しないよう、既知のabortコードを除外する。
- 英日migration guideの対応一覧に`number`と`range`を正式統合した。補足注記を削除し、number/rangeがstringを保持し`valueAsNumber`へ変換しないこと、rangeの補正がnative semanticsに従うことを記載した。
- roadmap冒頭とM18.14 milestoneを完了状態へ更新した。

Runtime/APIは変更していない。bundle budgetも変更していない。

## ブラウザー観測

観測環境はwebsiteの静的buildをPages base path `/react-fine-grained-signals/`で配信したPlaywright smoke。

| 操作 | Chromium | Firefox |
|---|---|---|
| マウスでtrackを押す | 成功、Signal/表示とも96 | 成功、Signal/表示とも94 |
| `End`, `Home`, `ArrowRight` | 100 → 0 → 1、Signal/表示同期 | 100 → 0 → 1、Signal/表示同期 |
| native event | `input`後に`change`。React `onInput`から更新済みSignalを観測 | 同じ順序を確認 |
| owner render | マウス・キー・Signal更新による追加renderなし | 同じ結果 |
| Signal `120`, max `100` | Signalは120を保持、DOMは100 | 同じ結果 |
| min/max/stepを10/80/5に変更 | DOMはmax 80に補正 | 同じ結果 |
| Signal `73`、step 5 | Signalは73、DOMは75 | 同じ結果 |
| `range`から`text`へtype変更 | DOMの75を保持し、Signalは73 | 同じ結果 |
| 外部Signalを55へ変更 | DOM/表示が55へ同期 | 同じ結果 |

WebKitでも同じ全操作が成功し、track操作の値は97だった。3 engineそれぞれで全Website smokeが最後まで成功し、Hydration/console/requestの警告・失敗はなかった。

rangeからtextへの切替時にDOMが75のままなのは、bindingがmount後にReactから値を再制御されないuncontrolled bindingであることと、入力要素のnative type切替が現在のDOM値を保持する挙動による。Signalが変更されるとDOMは新しいSignal値へ同期する。値をtype変更のたびに押し戻す処理は追加しない。これは`src/runtime/jsx.ts`の既存方針（Reactの再diffがDOM値を触らないよう二方向bindingでは初期値をuncontrolled propとして渡す）に沿う。

Chromiumの最初のsmokeでは、trackの75%位置がthumbに近く値が十分移動しなかったため、実操作点を90%へ変更した。Chromiumは値96、Firefoxは94となり、どちらも単調なnative slider位置と一致した。type切替の初期期待値もSignalへ強制再同期する想定から、観測したnative DOM保持契約へ修正した。

## ドキュメント

移行ガイドの正式な`bindValue`対応一覧はtext系・number・range input、textarea、single/multiple select。unsupported input typeと既存migration errorは維持した。number/rangeのSignal型は`FormBindableSignal<string>`。
