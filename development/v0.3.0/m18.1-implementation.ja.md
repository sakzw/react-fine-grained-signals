# M18.1 — Independent Vocs Documentation Site

## 目的と範囲

`website/`に独立したpnpmプロジェクトとしてVocs 2のドキュメントサイトを追加する。英語の初期ガイドとReact client demosを含める。ライブラリ本体の公開、version、tagは変更しない。

## package管理とローカル開発

- サイトは専用の`website/package.json`、`website/pnpm-lock.yaml`、`website/pnpm-workspace.yaml`を持つ。workspaceは`packages: []`で閉じ、親の`packages/*`を参照しない。
- RFSG v0.3.0とunplugin v0.3.0は未公開のため、repository development modeでは`node scripts/prepare-repository.mjs`がそれぞれの`pnpm pack`を実行し、サイト内のgitignored `.repo-packages/`にtarballを作る。サイト依存はそのtarballを`file:`で参照する。ソースコピーも親workspaceリンクも使わない。
- 新規cloneでは最初に`node website/scripts/prepare-repository.mjs`を実行してから`pnpm --dir website install`する。tarball生成にはルートのpnpmが必要。以降のsiteコマンドはwebsiteの依存から実行する。
- Standalone modeへの移行時はwebsiteのpackage依存2件を公開済みnpm semverに置き換え、website内でlockfileを更新する。アプリコード、MDX、Vite/Vocs設定は変えない。現状、未公開の0.3.0をnpmから取得するstandalone installは検証できない。
- ReactとReact DOMはwebsite側で一度だけ依存し、Viteでdedupeする。

## Vocs構成

`website/vocs.config.ts`は`srcDir: 'docs'`、`renderStrategy: 'full-static'`、プロジェクトサイト用`basePath`を指定する。`VOCS_BASE_PATH`でPages project pathを上書きできる。Vite側はManaged Transformを`src/demos.tsx`だけに限定し、RFSG JSX runtimeを同ファイルのpragmaで使う。デモモジュールは`'use client'`境界を持つ。

## ページとドッグフーディング

初期ページはIntroduction、Installation、Getting Started、Core Signals、React Hooks、Managed Transform、JSX Direct Binding、Deep Signal / Collections、Interactive Examples。既存の`docs/guides/`は原本として残し、サイトページは利用者向けに圧縮・再構成した要約と原本へのリンクを持つ。完全な文章を二重管理しない。

デモはCounter、Computed、Deep Signal、Form Binding、For / Index、JSX direct binding、Managed Transformをカバーする。Transformは実Vite buildで処理する。

## 検証記録

すべて`website/`をcwdとして実行した。Vocs CLIが標準では外部Vite設定を読み込まず、`configFile: false`で`react()`と`vocs()`を生成するため、`scripts/vocs.mjs`で同じplugin構成にManaged Transformを加えてVite dev/buildを起動する。transform対象はデモモジュール1つに限定する。

- install: `node website/scripts/prepare-repository.mjs`でruntimeとunpluginを各packageの`pnpm pack`からtarball化した後、`pnpm --dir website install --frozen-lockfile`成功。さらにwebsiteの設定・ソース・tarballだけを親repo外のtempへ複製し、そこでのfrozen installも716 packagesで成功した。site lockfileだけで完結し、親のpnpm workspaceには参加しない。
- TypeScript: `pnpm run typecheck`成功。
- dev: `pnpm run dev`で`http://localhost:5173/react-fine-grained-signals/`を起動。初回route要求はWaku/ViteのRSC/SSR/client dependency optimizeとMDX compileに約3分かかったが、その後examples routeはHTTP 200で描画した。Chromiumで7種類のdemoを操作し、Console error / page errorは0件。
- production build: `pnpm run build`成功。Vocs `full-static`の5段階を実行し、25ファイルを生成。Vite buildでManaged Transform pluginが実行された。静的出力は`website/dist/public/`。
- preview: `pnpm run preview`で起動し、`/react-fine-grained-signals/examples`がHTTP 200、`text/html`で返ることを確認。
- GitHub Pages basePath: 全9ページのskip link、ナビゲーション、asset URLに`/react-fine-grained-signals/`が付く。出力HTML12件を検査し、誤ったroot-relative skip linkは0件。examples pageではbasePath付きasset referenceを41件確認。
- SSG/hydration/interaction: ChromiumでCounter、Computed、Deep Signalのname/city両入力、`bindValue` Form Binding、Forの追加とIndex選択、style direct binding、Managed Transformのsignal更新を確認。SSR初期値から操作後の更新まで一致し、hydration mismatch、Hook violationを含むConsole errorは0件。
- standalone npm install: 未確認。runtime/unplugin v0.3.0は未公開のため、registryからのinstallは実行できない。npm依存への切替手順は上記に記載。

## 既知のコストと制約

- Vocs/Wakuの初回dev route要求はこの環境で約3分。2回目以降は依存cacheを利用する。ドキュメントサイトの開発体験として引き続き監視する。
- Vocsのclient bundleに`playground-modal.client`約2,995 kB (gzip約914 kB)のchunk warningが出る。コード例のPlayground機能に由来し、Vocs側のchunkなのでRFSG本体のサイズではない。ユーザーがPlayground modalを開く前にもロードされるか、将来のbundle budgetで確認する。
- build中のVocs server-side `OpenApiPage` chunkは約9.7 MB。full-static build後に静的専用chunk 11個がserver bundleからpruneされ、Pages配信用public outputには不要なserverは置かれない。
- `website/`を単独cloneしたrepository-development modeでは、ローカルtarballを作る入力sourceがない。Standalone運用への移行時はpackage.json内の2つのfile依存を公開npm semverに置換してlockfileを再生成する。

親リポジトリへの変更は本記録、ロードマップ、websiteソースに限定する。
