# M9.1 Form Binding Completion

実施日: 2026-10-14
基準: `main` / `770b0e13d17897cb84b8696b5457be554bdec387`

## 対応内容

M9で未接続だったselect向けの`select-value` bindingを、明示APIの`bindValue`から利用できるようにした。既存の`setSelectValue()`、`bindSelectValue()`、ref単位のsubscription lifecycleを維持して、native `change`によるsignalへの書き戻しとform reset同期を追加した。

- 単一selectは`Signal<string>`、`multiple` selectは`Signal<string[]>`を受け付ける。payloadと現在のselect modeが違う場合はruntimeで拒否する。
- signal変更はReact ownerの再renderなしにDOMへ反映し、同じ値のDOM writeは省略する。
- native `change`は単一値を`select.value`から、複数値を`selectedOptions`からoption文書順でsignalへ反映する。Reactの`onChange`はそのまま動作し、handler実行時にはsignalが更新済みである。
- option subtreeのchildListを1つのMutationObserverで監視し、option追加・削除後に現在のsignal値とdefault selectionを再適用する。observerとchange/reset listenerはbinding teardownで解除する。
- signalが最後にDOMへ適用した値をreset defaultにも同期する。受理されたresetの後にDOMを現在signal値へ戻し、`preventDefault()`されたresetは変更しない。
- SSRはReactの`defaultValue`経由で初期選択を出力し、hydration後はbindingが既存nodeへ接続する。
- BindingKindから旧signal-valued `value` select経路と不要なuncontrolled mappingを削除した。

## React propsとの所有権

`bindValue`と`value`/`defaultValue`、`bindChecked`と`checked`/`defaultChecked`の併用をruntimeで拒否する。型はinput/textarea/select/checkboxのbinding armとReact標準prop armをunionで分離し、selectの`multiple` literalとSignal payload型を対応させた。動的`multiple: boolean`はbinding型として拒否し、JavaScriptや型castで回避されたケースはruntimeで実際のDOM modeを検証する。

React標準のcontrolled selectは引き続き`value={selected.value}`と`onChange`で使用できる。`bindValue`にはsignalへの追加代入を要求しない。値を拒否・補正する場合、`onChange`内でsignalへ有効値を書き戻すとbindingがDOMを同期する。handlerが編集を無視するだけでは入力は拒否されない。

## v0.2.1との差

v0.2.1のselectはsignal-valued `value` propsによる暗黙bindingだった。M9.1はv0.2.1 APIとの互換性を持たせず、M9のexplicit APIである`bindValue`へ統合した。複数選択は同じく配列値だが、DOMからの値は`selectedOptions`のoption順でsignalへ入る。従来のmanual `onChange`書き戻しは不要。React標準のcontrolled propはこれまでどおり別の契約である。

## E2E起動順序

Playwrightの複数webServerが独立して起動し、それぞれのcommandがunpluginの同じ`dist`をbuildしていた。Vite dev serverが他のbuild中にdistをimportし、欠落／途中のmoduleを一時解決できなくなる競合を取り除くため、`test:browser`の前段でtransform、production browser、React Routerを直列buildする。webServer commandは既成buildのserver起動だけを行う。単独の`dev:browser`と`build:browser` scriptは引き続き利用できる。

Playwright server portは`RFSG_E2E_DEV_PORT`、`RFSG_E2E_HMR_PORT`、`RFSG_E2E_PRODUCTION_PORT`、`RFSG_E2E_REACT_ROUTER_PORT`で上書き可能にした。検証中に古い既存serverを再利用した試行ではReact Router asset hash不一致が起きたため、専用portかつCI modeでfresh build/serverを再確認した。
