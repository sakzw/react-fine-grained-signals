# M17.4 — v0.2.1以降の全変更レビューと指摘の解消

開始基準: `main` / `6d9d5b425c210c853c3e262b002862d0d8fbe699`(M17.3記録時点)
比較基準: tag `v0.2.1` / commit `58f01b9314a1b09b88b162c57912ff736201e790`

## 結論

v0.2.1から開始時点のmainまでの全変更を、5つの独立したレビューエージェントでレビューした。対象領域は次の5つ。

- core / deepSignal
- JSX runtime / form binding
- React統合
- transform
- 公開API・型・docs・packaging

各指摘は、エージェントが実行して再現したものを主体に、主要なものは私が個別に再現を確認した。指摘はblocker 1件、major 9件、minorが多数あり、ユーザーの指示によりminorも含めて全件をこのmilestoneで修正した。

修正ごとに再現テストを追加した。修正前のコードで失敗することは、jsx、React、sweepなど該当するものについて確認している。公開APIの追加・削除はない。型レベルでは、`FormBindableSignal<T>`の型専用brandを反変にした(後述)。

## 主な指摘と修正

### transform(`85a1924`)

| 指摘 | 重要度 | 修正 |
|---|---|---|
| `z.schema().opt(x)…`のような呼び出しchainで変換時間が指数的に増加(18段で約44秒) | blocker | tracked readの判定をalias集合と関数ごとにmemo化した。40段で約70ms |
| `user?.value!.name`でoptional chainがcaptureに分断され、TypeError | major | `!`/`as`/`satisfies`を透過して、chainのobject、callee、tagged templateのtagであることを判定する |
| `box.value.get!()`や`(… as T)()`でmethodの`this`が失われる | major | 同上。call全体をcaptureする |
| v0.2.1では追跡され、v0.3では無警告でstaleになるread | major | 下の一覧 |
| `useEffect`/`useCallback`で誤ったHook警告、重複警告、closure defaultへの誤警告、capture済みhelperへのdestructuring警告 | minor | Hook自身のcallは判定対象外にした。警告をsiteごとに1回にした。parameter default内の関数を除外した。destructuring警告は、patternをcaptureするようになったため廃止した |

次の形はすべてcaptureするようにした。

- destructuringのloop headを含む、あらゆるdestructuring宣言と代入。記述どおりの評価を1つのcapture内で行い、bindingをaliasとして追跡する
- callに渡した名前付き関数(`items.filter(isSmall)`)
- JSX spread props
- 後から代入する`let` alias
- object literalのgetter
- `??=`や`+=`のような読み取りを伴う代入
- Hookの結果に対する`for...of`

Hookを呼びつつsignalを読む関数をplain call(`{Title()}`)した場合はcaptureできない。この場合は警告を出す。

### core / deepSignal(`3d544e4`, `04c757d`)

| 指摘 | 重要度 | 修正 |
|---|---|---|
| object memberを持つSetで`union`/`difference`/`isSupersetOf`などの結果が誤る | major | GetSetRecordと同じ検証を行い、raw memberとproxyのidentityを双方向に変換するset-like recordをnativeへ渡す |
| Dateやclass instanceを含むgraphの保存が約12倍遅い | major | prototype chainが`Object.prototype`に届く値には、例外を投げるbrand probeを行わない。2000行の保存で752→27ms |
| 無関係な書き込みが、render中のattemptを無効化する | minor | mutation直後の同期sweepでは、render中に読まれたkeyを解放しない。後のtaskのsettled sweepで解放とrevision更新を行う |
| interop protocol getterが、継承receiverや無関係なreceiverでthrowする | minor | prototype chainからsignalを解決し、見つからなければ`undefined`を返す |
| `getOrInsert`などupsert methodがbindされずに漏れる | minor | reactiveな`has`/`get`/`set`から構成する。`emplace`は拒否する |
| opaque値のreadとcollection反復のhot path | minor | `wrap()`でplain判定を1回にした。iteratorは共有の`next`を持つclassにした。小さいMapの反復が約4倍速い |

### React(`36e8934`)

| 指摘 | 修正 |
|---|---|
| `yield*`は委譲先のresult objectをそのまま返すため、generatorをfast pathに置くとgetter readが漏れる | generatorをfast pathから外した |
| `useSignalCapture`が、前の兄弟の開いたbare scopeを閉じない | managed scopeのpush時と同様に閉じる |

### JSX form binding(`a002a78`)

| 指摘 | 重要度 | 修正 |
|---|---|---|
| `preventDefault()`したhandlerがcontrolをunmountすると、signalが変更されたまま残る | major | dispose後もsettleを実行する(signalと登録中のmemberだけを触る) |
| radioのsetterが別のoptionへ正規化すると、Reactの`onChange`が発火しない | minor | click中は、targetと同じnative group内のpeerのDOM書き込みも遅延させる |
| selectの拒否・正規化がReactの`onChange`より前にDOMへ反映される | minor | textと同じく次のtaskで補正する |
| cancelしたcheckbox group clickの直後に別memberをclickすると、cancel分が残る | minor | そのoptionのmembershipだけを戻す。次のclick前にpending settleを適用する |
| `undefined`のbinding propが型を通るのにruntimeでthrowする | minor | 指定なしとして扱い、DOMにも渡さない |
| setterが例外を投げるとDOMとsignalがずれる | minor | text、checkbox、groupのいずれも、補正をscheduleしてから再送出する |
| `bindChecked`がdisabledを確認しない | minor | 確認する |
| SVG/MathML hostで`bindValue`がDOMへ渡る | low | 他の非form要素と同じく、signalならthrowし、`undefined`なら除去する |
| text input/textareaのbindingが`signal<"a"\|"b">`を受け付ける | minor | `FormBindableSignal<T>`の型専用brandを`(value: T) => void`にした。radio、select、checkbox groupは、内部型`FormBindableChoiceSignal`で狭いunionを引き続き受け付ける |

### docs(`630f0f6`)

- **migration guide**
  - 存在しなかった`collections` optionの記述を削除した
  - accessorを持つ、またはseal・拡張不可のentryも保存時にthrowすることを記載した(初期値を含む)
  - TypeScriptの変更の節を追加した
  - groupの`value`と`undefined` propの例外を記載した
  - destructuringの行を新しい挙動に合わせた
- **hooks guide**: depsを指定した`useComputed`は、depsが変わると別のcomputedを作り、identityが変わる。実装どおりの記述に修正した
- **jsx-bindings**
  - 英語版で欠けていたgetter例外の制約を復元した
  - 動的`multiple`にはcastが必要であることを記載した
- **core-primitives、runtime entryのJSDoc、plugin README**: 現行の型と役割に更新した

## 確認

  - core: collection 4件、interop 1件

  - JSX: 7件

- lint: 成功

  - transform suite: esbuild adapterのbuild 3件は手元で5秒timeoutになったが、変更前のHEADでも同じであり、環境要因と判断した
  - runtime binding、collection、React関連のtest file
- 全suite、coverage、build、consumer/mixed-version smoke、size budget、Browser E2Eは、GitHub Test/E2Eで確認する(下記)
- Fast Refresh harnessはCI対象外で、今回は手元で実行していない。transformの出力形が増えたため、次回のrelease checklistで実行する

## 残る制約

- 上記以外の新しい既知制約はない。M17.3までの制約は次のとおり。
  - custom iteratorの反復コスト
  - `for await`と`for (x of gen())`は変換対象外
- `preventDefault()`と、clickした値と同じ値を同期的に書く組み合わせは、引き続き区別できない(guideに記載済み)
- Hookを呼びつつsignalを読む関数のplain callは、captureせず警告を出す
