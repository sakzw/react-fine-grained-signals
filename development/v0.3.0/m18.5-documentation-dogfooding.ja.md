# M18.5 Documentation & Consumer Dogfooding

## 目的と範囲

M18.1〜M18.4で用意した独立Vocs環境を、英語の実用ガイドとConsumerデモで拡張した。v0.3.0のrelease freeze/publication準備は行わず、ライブラリruntime/APIにも変更を加えていない。

## ドキュメント

- 既存の9ページを維持し、Control Flow、Shared State、Rendering Optimization、Migrationの4ページを追加。
- Managed TransformページにRFGS001〜RFGS009、`diagnostics.errorOn`、React Compiler順序とmemoization、Fast Refreshの既知契約を追加。
- `docs/guides/`と`docs/migration/`の英日Markdownを完全なAPI/migration正本とする。websiteは英語の短い説明と実行例を持ち、各ページから正本へリンクする。websiteは親リポジトリのファイルをimportしないため単独移設可能。意味論を変える場合は正本を先に更新し、website側の要約・例を追随させる。

## Consumerデモ

- Form Bindingにsingle/multiple selectを追加。DOM変更からSignalへ、Signal presetからDOMへの両方向を確認する。
- For/Indexに追加・削除・並べ替え・immutable replacement・ネストしたDeep Signal変更を追加。list owner、keyed/position row、deep rowの描画回数を表示する。
- Shared Stateで独立したManaged Transform consumerと`useSignalValue` consumerが同一module-level client signalを読み、書き込み後に共通ownerを再描画しないことを表示する。
- Show/Switch/Matchの操作デモを追加。特別なRuntime APIやライブラリ依存は追加していない。

## dogfoodingで確認した契約

- `For`はコレクション変更時に全itemの`by`/children callbackを呼ぶ。keyはReact row identityを保つがcallbackの実行は省かない。
- immutable replacementはコレクション更新であり、For出力を再構築・React reconciliationする。一方、row component内でDeep Signalのネストプロパティを読み、そのrow自身に追跡境界を置くと、該当rowだけを更新できる。どちらも既存仕様で、Runtime修正は不要。
- Shared Stateのmodule singleton例はclient-onlyに限定する。SSRではprocessをまたいで値が共有され、request dataの漏えいとhydration不一致を招く可能性がある。request固有値にはper-request store + Contextを使用する。
- 再現するTypeScript/RFSG runtime/Managed Transform不具合は見つからなかった。変更対象はwebsite/docs/smokeのみ。
