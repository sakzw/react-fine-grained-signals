### 互換性とworkflow条件

- checkout v7、configure-pages v6、Pages deploy/artifactの現行世代はNode 24 runtimeを使う。Node 24 ActionsにはActions Runner `2.327.1`以上が必要。`ubuntu-latest`を使い、E2E/Website CIのPlaywright containerもhost側の現行runnerで実行する。
- checkout v7はforkからの`pull_request_target`/`workflow_run` checkoutを既定で制限する変更を含む。Test/E2Eは通常の`pull_request`のみで、checkoutに追加inputを渡さないため該当しない。
- `pnpm/setup`は`pnpm/action-setup`とは別Action。v3はpnpm 11以上を対象とし、package managerのnative binaryとNode/runtimeを扱う。repositoryはpnpm 12.8.1で適合する。rootはmanifestの`devEngines.runtime`(Node 24.21.0)を使用する。Website側は`working-directory: website`、`runtime: node@24.21.0`、`cache-dependency-path: website/pnpm-lock.yaml`を明示し、親workspaceではなくstandalone lockfileでcacheする。
- Website側のpnpm setupでは`install: false`にする。repo-local package tarballの生成後に`pnpm install --no-frozen-lockfile`を行うためである。これでtarball integrityの更新を許容しつつ、CI cache keyはwebsite lockfileに結び付く。
- deploy workflowはpush/PR triggerを持たず`workflow_dispatch`だけを持つ。build jobは`contents: read`と`pages: write`、deploy jobは`pages: write`と`id-token: write`を持つ。`github-pages` environmentのURLはdeploy actionの`page_url`を参照する。Pagesのsourceは利用者が事前にGitHub settingsでActionsにする必要があるが、本作業では設定変更していない。
- upload-pages-artifactの`include-hidden-files: true`で`.nojekyll`をartifactへ含める。artifact pathは`website/dist/public`。buildとdeployは別jobで、deployはbuild成功後に限る。

## Website CIとPages workflow

- `.github/workflows/website-ci.yml`を追加した。Website、runtime、unplugin、root package/lock、関連build configの変更で動き、既存Test/E2Eを再実行しない。repositoryのライブラリとunpluginをconsumer tarballとしてpackし、Website専用install、typecheck、静的build、既存Chromium smokeを実行する。
- `.github/workflows/website-deploy.yml`を追加し、以前の非アクティブtemplate `website/deploy/github-pages.yml`を削除した。実行triggerは手動のみ。`configure-pages`の`base_path`を`SITE_BASE_PATH`へ渡し、GitHub Pages project pathまたはcustom domain pathでbuildする。
- `website/scripts/smoke.mjs`に`.nojekyll`の静的preview確認を追加した。404 HTML、favicon、CSS、JS、basePath下の直接アクセス、skip link、client navigationとデモ操作も既存smokeが検証する。
- npm公開後は`website/package.json`のfile tarball dependencyを通常のregistry dependencyへ置き換え、ローカルpack/install stepを外す。現時点ではv0.3.0未公開のためStandalone modeのnpm installは検証不能。website package/lockfile自体は独立を維持する。

## skip link補正の保守性

Vocs 2.10.3の`SkipToContent.client.tsx`はrouter pathから`href`を生成し、`basePath`を付与しない。そのためGitHub Pages project siteでは静的HTML上のskip linkがrepository pathを欠く。Vocsにこのcomponentの設定hookは見つからず、Vocs内部componentのpatchやsource importはupgradeに弱いため採用しない。

`website/scripts/fix-base-path-links.mjs`は静的build後に、Vocsの`data-v-skip-to-content`要素だけを現在のroute + basePathへ補正する。生成markupから対象を絞り、該当linkが0件なら失敗させる。今回のsmokeでは全9 routeのskip linkを検査した。Vocsのmarkup変更でscriptが外れたときにCIが検出するため、この小さなpost-build workaroundを維持し、Vocs更新時に再確認する。

## 初回アクセスのJavaScript/CSS量

新規Chromium contextで静的previewを各routeへ直接表示し、実際に取得されたdocument/JavaScript/stylesheet response bodyを集計した。`serve-static.mjs`は圧縮を行わないため、raw bytesはpreviewでの実取得量、gzip列は同じresponse bodyをgzipした比較値であり、GitHub Pages/CDNの実転送量を計測した値ではない。GitHub PagesはdeployしていないのでCDNのgzip/Brotli挙動は未検証。

| Page | JS requests | JS raw | JS gzip | CSS requests | CSS raw | CSS gzip |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `/` | 20 | 740,157 B | 240,395 B | 2 | 155,960 B | 23,339 B |
| `/examples`（7つのdemoすべて） | 23 | 693,279 B | 226,543 B | 2 | 155,960 B | 23,339 B |
| 他の7 guide route | 17–20 | 669,334–741,826 B | 218,261–241,029 B | 2 | 155,960 B | 23,339 B |

HTMLを含めたgzip換算初回body量はhome約275 KB、examples約260 KB。静的出力は282 files、13,734,399 bytes(約13.1 MiB)。全出力の大半は遅延読み込みのsyntax/highlight、playground等であり、first-loadのJS/CSSは全出力より小さい。デモページではCounter/Computed/Deep Signal/Form/For-Index/JSX binding/Managed Transformをすべて操作している。初回routeでさらに大きなchunkを同期取得する無駄は見つからず、性能最適化は今回は加えない。

## 検証

- `node website/scripts/pack-local-rfsg.mjs`: runtimeとunpluginを各`prepack`経由でtarball作成。
- `cd website && pnpm install --no-frozen-lockfile`: success (`pnpm 12.8.1`, already up to date)。既存のtarball integrityが変わる可能性を許容するCIと同じinstall mode。
- `cd website && pnpm typecheck`: success。
- `cd website && pnpm build`: success。`dist/public`へ25 routeファイルを生成、9 skip linkを補正。
- `cd website && pnpm smoke`: success。各routeの直接アクセス/stylesheet/skip link、favicon、`.nojekyll`、404、sidebar navigation、7 demoのSignal更新、console warning/error、failed requestなし。
- 静的resource measurement: Chromium新規contextで9 route成功。homepageおよびexamplesの実要求数とbody bytesを記録。
- Test/E2E workflowはこの作業中にローカルでは再実行していない。push後のActions runで既存CIとWebsite CIを確認する。Pages deploy workflowは実行しない。
